## Codebase Patterns
- Single-header convention: `#ifndef X_H` / `#define X_H` for declarations, `#ifdef X_IMPLEMENTATION` for implementation
- Arena allocator: zero-init `arena_t arena = {0}`, uses libc by default
- Test tracked allocator: `tracked_allocator` from `test/test_helpers.h`, plug into arena via `.allocator = tracked_allocator`
- Build system: `build.sh` with `TESTS=()` array entries formatted as `"path/test.c|name|optional_extra_cflags"`
- Compiler flags: `-Wall -Wextra -std=c99 -g`
- Relative includes from module dirs use `../` prefix (e.g., `#include "../arena/arena.h"`)
- Implementation language is C (C99)
- Existing modules: platform/ (atomics, threading), arena/ (bulk allocation), test/ (test harness), lexer/ (tokenizer), value/ (tagged value system), parser/ (AST + parser)
- Private/internal functions use double-underscore prefix: `module__function_name`
- Public types use PascalCase (Token, LexResult, AstNode) or lower_t for system-level (arena_t)
- Public functions use module_verb_noun pattern (lexer_lex, arena_alloc, parser_parse)
- Constants and macros use ALL_CAPS (TOKEN_EOF, JACL_TAG_NIL)
- Test functions are `static int test_name(void)` returning 0=fail, 1=pass
- Test main() uses table-driven pattern: array of {name, fn} structs, iterates and counts pass/fail
- Memory leak check pattern: setup() -> exercise -> teardown() -> ASSERT(check_no_leaks()) -> TEST_PASS()
- Tests grouped by US-XXX story comments in the test table
- Lexer token types: TOKEN_LBRACKET, TOKEN_RBRACKET, TOKEN_LBRACE, TOKEN_RBRACE, TOKEN_LPAREN, TOKEN_RPAREN, TOKEN_SEMICOLON, TOKEN_WORD, TOKEN_OPERATOR, TOKEN_INT, TOKEN_FLOAT, TOKEN_STRING, TOKEN_STRING_BEGIN, TOKEN_STRING_PART, TOKEN_STRING_END, TOKEN_INTERP_VAR, TOKEN_INTERP_EXPR_START, TOKEN_INTERP_EXPR_END, TOKEN_VAR, TOKEN_DOLLAR_BRACKET, TOKEN_NEWLINE, TOKEN_ERROR, TOKEN_EOF
- TOKEN_SEMICOLON added in US-006 — `;` is now a proper delimiter token (not TOKEN_ERROR)
- LexResult struct: Token* tokens, uint32_t count, uint32_t error_count
- Token struct: TokenType type, uint32_t line/column/offset/length, union payload (text/int_val/float_val/error_msg)
- TOKEN_VAR payload.text points into source buffer, skips the $ prefix
- Lexer API: LexResult lexer_lex(const char* source, arena_t* arena)
- Token array always ends with TOKEN_EOF

- Pretty-printer: ast_pretty_print (single node) and ast_pretty_print_program (top-level array) in ast.h implementation section
- Pretty-printer uses AstStrBuf (growable arena-backed string buffer) with ast__buf_* helpers
- AST_LIT_STRING quoting: bare words/operators print unquoted; strings with spaces, special chars, or leading digits get quoted with escaping
- Float pretty-printing: %g with decimal point enforcement (append ".0" if no dot/e in output) to avoid int re-parse
- Interp string pretty-print: text segments escape $, commands use $[head args] syntax
- Block pretty-print: { [cmd1]; [cmd2] } — commands always in bracket form, semicolon-separated
- Round-trip verification: parse → pp → parse → pp → strcmp — deterministic output means string equality proves structural equivalence

- AST node types: AST_COMMAND, AST_LIT_INT, AST_LIT_FLOAT, AST_LIT_STRING, AST_VAR_REF, AST_BLOCK, AST_INTERP_STRING, AST_ERROR
- SourcePos struct: uint32_t line, column, offset
- AstNode is a tagged union with SourcePos start/end and type-specific data union
- ast_alloc(arena) and ast_alloc_array(arena, count) helpers in ast.h header section (static inline)
- AST_COMMAND has head (AstNode*) + args (AstNode**) + arg_count — head is the command name node
- ParseResult struct: AstNode** nodes, uint32_t count, uint32_t error_count
- Parser API: ParseResult parser_parse(LexResult tokens, arena_t* arena)
- Parser internal: Parser struct (tokens, count, pos, arena, error_count), parser__peek/advance/at_end helpers
- Parser test helper: `static ParseResult parse(const char* source)` wraps lexer_lex + parser_parse
- Parser test helper: `static AstNode* parse_expr(const char* source)` wraps lexer_lex + parser__parse_expr for testing individual expressions
- parser__parse_expr dispatches: TOKEN_LBRACKET → parse_command, atom tokens → parse_atom, otherwise → NULL
- parser__parse_command handles [cmd args...], skips newlines inside brackets, returns AST_ERROR for empty [] or mismatched [
- parser__parse_bare_command: parses head expr + args until command end (newline/semicolon/EOF), wraps in AST_COMMAND
- parser__is_command_end checks TOKEN_NEWLINE, TOKEN_SEMICOLON, TOKEN_EOF
- Top-level bracket commands ([+ 1 2] with no trailing args) are returned unwrapped from bare command parsing
- parser_parse main loop: skip newlines/semicolons, parse bare commands, push to top_level array
- parser__parse_block: consumes { ... }, parses commands inside like top-level loop (newline/semicolon delimited), returns AST_BLOCK
- TOKEN_RBRACE is a command terminator in parser__is_command_end — bare commands inside blocks stop at }
- Blocks dispatch from parser__parse_expr via TOKEN_LBRACE case
- Blocks as command args work naturally: parse_expr dispatches to parse_block which consumes { ... }, so } never leaks to outer command parsing
- Interpolated strings: TOKEN_STRING_BEGIN dispatches to parser__parse_interp_string in parse_expr
- Lexer interpolation token sequence: STRING_BEGIN [INTERP_VAR|INTERP_EXPR_START...INTERP_EXPR_END] [STRING_PART [INTERP_VAR|...]]* STRING_END
- TOKEN_INTERP_VAR payload.text points past $ into source buffer, length includes $ — var_ref.length = tok->length - 1
- INTERP_EXPR_START/END bracket expression tokens that are parsed like a command: head + args until INTERP_EXPR_END
- Empty text segments (STRING_BEGIN/PART/END with empty payload.text) are skipped in AST — no empty AST_LIT_STRING nodes
- Non-interpolated strings (TOKEN_STRING) still produce AST_LIT_STRING via parse_atom, not AST_INTERP_STRING
- Panic mode bracket sync: parser__sync_bracket skips to matching ] tracking bracket depth, stops at newline or } at depth 0
- Error recovery in brackets: newlines inside brackets use peek-ahead (save/restore) instead of free skipping — if ] not found after newlines, restore position and break for error recovery
- parse_bare_command returns AST_ERROR head immediately (no arg parsing) so tokens after error remain for recovery
- parser_parse creates AST_ERROR nodes for unexpected top-level tokens (], }, etc.) instead of silently skipping
