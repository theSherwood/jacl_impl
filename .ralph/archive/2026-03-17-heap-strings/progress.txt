## Codebase Patterns
- sum_tree.h is an include-as-template header — define STREE_T, STREE_SUMMARY_T, STREE_NAME before including; also define STREE_GC_ALLOC(obj_type, sz), STREE_GC_OBJ_INTERNAL, STREE_GC_OBJ_LEAF for GC allocation (falls back to allocator-based malloc if not defined)
- JACL tests that allocate via GC must set `gc__current_heap = &heap;` after `gc_heap_init()` — the STREE_GC_ALLOC macro uses this TLS variable
- jacl.c is a unity build — include order matters: gc.c must come before rope.h so gc_alloc and GCObjType are visible to sum_tree.h macros
- Standalone lib tests (test_sum_tree.c, test_rope.c etc.) cannot check for memory leaks via `check_no_leaks()` since unref is now a no-op — memory is freed by `tracker_reset()` at the start of the next test
- Under GC, transient COW always clones (no refcount to check exclusive ownership) — COW path is slower than persistent path but still correct
- After US-004: rope_ref/rope_unref are no-ops, all rope_st_ref/rope_st_unref/rope_st_rc_* calls removed from rope.h, RC stubs removed from sum_tree.h
- After US-005: GC now traces rope trees — OBJ_ROPE_STRING pushes root.node, OBJ_ROPE_INTERNAL pushes children[0..n_children-1], OBJ_ROPE_LEAF is a leaf type. gc__finalize_dead no longer calls rope_unref.
- After US-006: JaclInternTable has a platform_rwlock_t lock. jacl_intern uses read-lock for lookup, write-lock for insert with re-probe. intern_table_destroy must be called to release the rwlock.
- After US-007: Intern table has tombstone support (INTERN_TOMBSTONE = (JaclHeapString*)1). gc_sweep_intern_table evicts dead entries when load > 0.75, otherwise marks them live. intern__find_slot probes past tombstones. Compaction triggers when tombstone_count > cap/4. Intern table NOT scanned as roots in gc_mark (full GC); still scanned in gc_mark_minor.
- After US-008: count_objects_of_type heap walker can miss live objects after zeroed dead objects within the same GC line — use direct GCHeader pointer checks (gc_header_of(ptr)->alloc_total > 0) instead. Tests use VM + gc_collect for full GC, RememberedSet + gc_collect_minor for minor GC. Structural sharing verified via rope_concat creating shared subtrees between two ropes.
- After US-009: jacl_intern's read-lock and write-lock fast paths must check `*slot != INTERN_TOMBSTONE` in addition to `*slot != NULL` — intern__find_slot returns tombstone slots for insertion, not as matches. To test eviction with load > 0.75, use intern_insert_direct helper that bypasses jacl_intern's resize (normal inserts cap at exactly 0.75). gc_alloc sets mark=0 and initial current_mark=1, so a single gc_collect suffices to evict unrooted objects.
- After US-010: Multi-threaded intern table tests need per-thread ThreadHeap via gc_heap_init with a shared BlockPool. Thread heaps MUST stay alive while gc_sweep_intern_table can reference their objects — destroying a heap returns blocks to the pool where they may be zeroed and reused, causing use-after-free in intern table entries. Use THREAD_CREATE/THREAD_JOIN from platform.h, compile with -lpthread.

  - jacl_run creates a stack-local JaclInternTable — must destroy the rwlock on every exit path (compile error, VM exec error, CPS error, normal return)

  - intern__resize and intern__find_slot are lock-free helpers — locking is done at the jacl_intern level only
  - All 62 existing tests pass unchanged — the rwlock is transparent to single-threaded code

## 2026-03-17 - US-007
- What was implemented: Intern table weak-reference eviction with tombstone support. Dead interned strings are evicted during full GC when load factor exceeds 0.75, preventing unbounded memory growth.
- Files changed:
  - src/string.c — Added INTERN_TOMBSTONE sentinel ((JaclHeapString*)1), tombstone_count field to JaclInternTable, modified intern__find_slot to probe past tombstones and reuse first tombstone slot for inserts, refactored intern__resize into intern__rehash with intern__compact for same-capacity rehash, jacl_intern now triggers compaction when tombstone_count > cap/4 and accounts for tombstones in load factor check
  - src/gc_collect.c — Removed intern table from gc_mark root scanning (section 4), added gc_sweep_intern_table function (called after mark, before sweep, during full GC only), gc_collect now calls gc_sweep_intern_table between mark and sweep phases
- **Learnings for future iterations:**
  - Removing intern table from roots creates a correctness hazard: dead entries become dangling pointers after sweep. gc_sweep_intern_table handles this by either tombstoning (when load > 0.75) or retroactively marking entries as live (when load <= 0.75)
  - The tombstone sentinel (JaclHeapString*)1 works because GC objects are 8-byte aligned — address 1 is never valid
  - intern__find_slot with tombstones must continue probing past tombstones to find existing entries that were inserted after the tombstoned entry — returning early at a tombstone would break the linear probing invariant
  - Intern table remains as roots in gc_mark_minor (minor GC) since gc_sweep_intern_table only runs during full GC
  - intern__compact and intern__resize share intern__rehash — compact uses same capacity, resize doubles it
  - All 62 existing tests pass unchanged

## 2026-03-18 - US-010
- What was implemented: Test suite for concurrent intern table access — 4 tests covering all acceptance criteria
- Files changed:
  - test/test_concurrent_intern.c — new test file with 4 tests: 8 threads × 1000 unique strings (count==8000), 8 threads × same 100 strings (count==100, no duplicates), 4 readers + 4 writers (concurrent read/write lock), concurrent interning during GC eviction (no corruption)
  - build.sh — added test/test_concurrent_intern.c to TESTS array with -lpthread flag
- **Learnings for future iterations:**
  - Each thread needs its own ThreadHeap via gc_heap_init(&heap, shared_pool) — gc_alloc uses explicit heap parameter, not gc__current_heap TLS (which is only needed for STREE_GC_ALLOC macro)
  - Thread heaps must NOT be destroyed while gc_sweep_intern_table can reference their objects — destroying a heap returns blocks to the shared pool where gc_block_pool_get zeroes them, causing use-after-free. Store heaps in thread args and destroy after verification.
  - gc_sweep_intern_table checks GCHeader marks on objects from other threads' heaps — objects have mark=0 from gc_alloc, which may not match the main heap's current_mark. This causes entries to be alternately evicted/retroactively-marked across GC cycles, providing good stress test coverage.
  - For tests without GC (tests 1-3), thread-local heap destruction at end of thread function is safe — blocks are returned to pool but not reused since no gc_block_pool_get follows.
  - arena_alloc is NOT thread-safe, but intern__resize/compact calls are protected by the intern table's write lock, so the shared arena used for entries arrays is effectively serialized.
