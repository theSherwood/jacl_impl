## Codebase Patterns
- Unity build: jacl.c includes all .c files in order (value.c -> gc.c -> rope.h -> string.c -> collections.c -> compiler.c -> vm.c -> gc_collect.c)
- Tests use test_helpers.h with ASSERT macros, return 1 for pass / 0 for fail
- E2e tests use jacl_run() with PrintCapture to verify compiled+executed JACL source output
- E2e embedding tests use jacl_vm_new() / jacl_eval() / jacl_vm_free() API
- build.sh compiles all tests in parallel, runs sequentially, reports summary
- TOKEN_DOTDOT already lexed in lexer.c but not compiled
- Existing CPS transform handles await/spawn/parallel/race — yield follows same pattern
- GC object types in gc.c enum, value tags in value.c, type enum in compiler.c
- Struct types tracked in StructTypeRegistry with field names, types, offsets
- Operator desugaring (= : ::) converts to def/mut/set AST nodes in parser
- Named destructuring ({x,y} = expr) uses same desugaring: parser detects {pattern} = or : and creates AST_DESTRUCTURE_NAMED → [def/mut pattern expr]
- Keyword form [def {x, y} expr] parses braces as AST_BLOCK; compiler detects simple block-of-words and converts to named destructuring
- For struct types known at compile time: compiler uses OP_STRUCT_GET per field (offset-based). For dyn/map: uses OP_DESTRUCTURE_NAMED opcode (runtime field lookup with error on missing keys)
- jacl_run() returns VM_RUNTIME_ERROR for both parse errors and compile errors — no separate compile error enum

- **Learnings for future iterations:**
  - {pattern} in keyword form [def {x,y} expr] is parsed as AST_BLOCK by the expression parser; the compiler converts it by checking block commands are bare words
  - OP_DESTRUCTURE_NAMED handles both struct and map at runtime: struct uses type registry field lookup, map uses HAMT key lookup with error on missing keys
  - Compile-time struct field validation catches missing fields early when struct type is known
  - For mutable destructuring in local scope, each field is extracted one at a time (OP_DESTRUCTURE_NAMED count=1) to allow OP_MAKE_CELL wrapping
  - For global scope, all fields are extracted at once then defined in reverse stack order (matching vec destructuring pattern)
