## Codebase Patterns
- Unity build: `src/jacl.c` includes all source files. Tests include `../src/jacl.c` directly. Compile tests as single translation units (e.g., `gcc test/test_foo.c -o test_foo -lm`), never pass individual .c source files alongside.
- Mutable variables (`mut`) use heap-allocated `JaclMutableRef` cells. The stack holds the cell pointer, mutations update the cell's value. This means mutations are visible across yields without needing special handling.
- Generator/yield uses CPS (continuation-passing style). The `is_generator` flag on closures triggers stream creation at call time. `OP_STREAM_NEXT` manages the PENDING→CONSUMED→EXHAUSTED state machine via CPS continuations.
- JaclStream stores: state, kind, next_fn (CPS continuation or generator closure), cached_value, and deferred args. `kind` distinguishes STREAM_KIND_GENERATOR (CPS-based) from derived streams like STREAM_KIND_FILTER. No coroutine state needed — CPS closures capture all state via upvalues.
- Derived stream pattern (filter/transform/take/lines): create a new JaclStream with kind=STREAM_KIND_X, store source stream + closure in args[]. The `vm__pull_stream_one()` helper handles all stream kinds (generator CPS protocol + derived stream logic). OP_STREAM_NEXT/OP_COLLECT/OP_EACH dispatch non-generator streams to this helper.
- `compiler__compile_hof_builtin()` preserves `last_expr_type` through the compilation: saves collection type before compiling callback, restores after emitting opcode. This means filter/transform on streams produce TYPE_STREAM and on vectors produce TYPE_VEC.
- The `def`/`mut` effective_type inference in compiler.c only auto-infers unboxed types, TYPE_STRUCT, and TYPE_STREAM. Other boxed types (TYPE_VEC, TYPE_MAP, TYPE_CLOSURE) fall back to TYPE_DYN. If adding a new type that needs compile-time dispatch (like TYPE_STREAM for for-loops), add it to the inference condition.
- While loop bodies need `compiler__begin_scope`/`compiler__end_scope` to properly clean up `def` locals each iteration (important for generators that yield inside loops).
- Some test suites (compiler, heap_strings, m4, m5, jacl_harness) time out under 10s but pass given more time. Use longer timeouts or skip these in quick validation.
- Build system (`build.sh`) compiles all tests in parallel, runs sequentially. Add new test entries as `"test/test_foo.c|foo|"`.
- New builtins follow the pattern: add OP_X to bytecode.c enum + name table, add `compiler__head_matches` check in `compiler__compile_command`, add `case OP_X:` in `vm__run`. Update test/test_bytecode.c opcode enum test when adding new opcodes before OP_HALT.
- OP_COLLECT implements the stream-to-vector protocol by inlining the OP_STREAM_NEXT logic in a loop: save caller context, invoke generator/continuation, handle VM_YIELD/VM_OK/error, restore context, repeat until EXHAUSTED.
- Stream-aware for loops: compiler emits TYPE_STREAM-specific path using OP_STREAM_NEXT + OP_IS_STREAM_EXHAUSTED in a pull loop. HOF/lambda callback forms (`for $stream $callback` and `for $stream [\ ...]`) dispatch through OP_EACH which already handles streams in the VM.

## 2026-03-19 - US-009 CPS Refactor
- Refactored yield/generator from coroutine stack save/restore to CPS (continuation-passing style)
- Files changed: src/compiler.c, src/vm.c, src/gc.c, src/gc_collect.c
- **Key design decisions:**
  - Generators are CPS-compiled: yield is a suspension point like await. The compiler adds __k as hidden last parameter.
  - OP_YIELD pops (continuation, value) from stack. Continuation is the CPS closure for remaining body.
  - OP_STREAM_NEXT creates a terminal_k closure (OP_RETURN only) and calls generator/continuation.
  - While loops with yield use recursive CPS: loop function with self-referencing mutable cell. Loopback closure shadows __k to re-invoke loop.
  - Suspension analysis: generators have `is_generator=true` in SuspensionMap. Calling a generator does NOT propagate suspension to the caller (it just creates a stream).
  - JaclStream simplified: removed saved_stack, saved_frames, resume_ip, resume_chunk. Only stores next_fn, cached_value, args.
  - Generator arity check in OP_CALL moved before is_generator check; uses min_args (excludes hidden __k).
- **Learnings for future iterations:**
  - CPS while-loop transformation: create cell for self-reference, build loop closure with __k param, build loopback closure that re-calls loop via cell, shadow __k with loopback before compiling body CPS.
  - Fixed TYPE_STREAM not handled in struct__type_size, struct__type_align (compiler.c), and embed__val_matches_field_type (embed.c) — always add new types to these switch statements.
  - Fixed unused `agg` variable in runtime.c runtime__parallel_task_exec.

  - Added `kind` field to JaclStream (STREAM_KIND_GENERATOR=0, STREAM_KIND_FILTER=1)
  - Added `vm__pull_stream_one()` helper function that handles pulling from any stream kind (generator CPS protocol + filter predicate loop)

- **Learnings for future iterations:**
  - Filter streams are lazy: no elements consumed until the result stream is iterated. Creating the stream just packages source + predicate.

## 2026-03-19 - Test Suite Fixes
- Fixed 15 test functions with infinite while loops across 4 test files (test_compiler.c, test_m4.c, test_m5.c, test_heap_strings.c)
- Fixed compiler bug: `continue` in while-loops with body-scope locals didn't pop those locals before jumping back
- Files changed: src/compiler.c, test/test_compiler.c, test/test_heap_strings.c, test/test_m4.c, test/test_m5.c
- **Root causes:**
  - `=` (def/immutable) used to "update" loop variables creates a shadowed binding leaving the outer variable unchanged → infinite loops. Must use `:` (mut) + `::` (set).
  - `continue` in while-loops emitted OP_LOOP backward jump without popping body-scope locals (e.g., `def` bindings inside the loop body), corrupting the stack.
- **Learnings for future iterations:**
  - While-loop variable updates MUST use `:` (mut) for init and `::` (set) for update, never `=` (def).
  - `continue` scope cleanup: for while-loops, pop `c->local_count - lctx->local_count_at_loop` locals via OP_POP_N before OP_LOOP. Do NOT apply this to for-loops — `local_count_at_loop` is set before for-loop hidden locals, so cleaning up would destroy iterator state.
  - `break` in while-loops with body-scope locals has the same issue in theory but existing tests don't exercise it. The for-loop break cleanup (`OP_CLOSE_LOOP`) already handles for-loop hidden locals correctly.
