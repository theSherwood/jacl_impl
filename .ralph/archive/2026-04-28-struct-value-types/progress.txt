## 2026-04-25 - US-005: Struct field access — byte-offset addressing

- OP_STRUCT_SET_INLINE: pops value, writes to inline struct field, pushes nil
- OP_STRUCT_MATERIALIZE: converts entire inline struct to heap-allocated JaclStruct (for `print $p`, return values, etc.)

- Sub-struct field access (TYPE_STRUCT field): emits OP_STRUCT_GET_INLINE with TYPE_STRUCT + type_idx to materialize; if chained, outer handler pops materialized value and uses byte-offset instead
- AST_VAR_REF handler: inline struct locals emit OP_STRUCT_MATERIALIZE for non-field-access use
- Added `ModuleBinding` typedef and `COMPILER_MODULE_BINDINGS_MAX` to `jacl.h` (were only in `compiler.c`) to keep Compiler struct in sync
- Updated bytecode enum test values (3 new opcodes at positions 126-128, HALT now 164)

## 2026-04-28 - US-010: Box struct values and deref/reset/swap
- New opcode: `OP_BOX_STRUCT` (uint16_t type_idx) — pops heap JaclStruct, allocates `sizeof(JaclMutableRef) + total_size`, copies struct data into box
- Compiler `[box $expr]` handler: checks `c->last_expr_type == TYPE_STRUCT` after compiling arg; emits OP_BOX_STRUCT + type_idx for structs, OP_BOX for non-structs
- Compiler `[atom $expr]` handler: emits compile error if `c->last_expr_type == TYPE_STRUCT` ("struct values cannot be stored in atoms")
- VM OP_BOX_STRUCT: validates type_idx, allocates JaclMutableRef with struct total_size, memcpy from JaclStruct.data
- VM OP_DEREF: if `ref->type_idx > 0`, materializes struct from box data[] into new heap JaclStruct (value copy)
- VM OP_RESET: if `ref->type_idx > 0`, validates struct type match, memcpy new struct data into box (no GC barriers needed for raw struct bytes)
- VM OP_SWAP: if `ref->type_idx > 0`, materializes current value as JaclStruct, runs closure, copies result back into box
- Updated bytecode enum test values (OP_BOX_STRUCT at position 68, all subsequent +1, HALT now 170)
- 5 new tests: box roundtrip (box→deref), reset (replace contents), swap (closure-based update), deref isolation (copy semantics), atom rejection (compile error)

- **Learnings for future iterations:**

  - Struct boxes don't need GC write barriers since struct data contains no GC references (value types only)

## Codebase Patterns
- In JACL, `$true`/`$false` are the boolean values; bare `true`/`false` are strings
- `jacl_f64_val(vm, val)` requires a JaclVM pointer as first argument (unlike `jacl_i32_val(val)`)
- Parser tests are independent of compiler validation — only test AST structure
- `Local` and `Compiler` structs are defined in both `jacl.h` and `compiler.c` — update both when adding fields
- `VM` struct is defined in both `jacl.h` and `vm.c` — update both when adding fields
- `JaclStateMachine` is duplicated in `jacl.h` AND `gc.c` — update both when changing its layout
- `JaclClosure` is duplicated in `jacl.h` AND `bytecode.c` — update both when changing its layout
- Bytecode enum values are tested with hardcoded integers in `test/test_bytecode.c` — update after inserting opcodes
- Test VM opcodes by constructing `BytecodeChunk` manually: `chunk_init`, `chunk_write`, `chunk_add_constant`
- JACL built-in commands use hyphens: `map-get`, `map-has`, `to-string`, `map-set` (not underscores)
- `JaclStruct` is duplicated in `jacl.h` AND `gc.c` — must update both when changing its layout
- Use `jacl_i32()` (value.c) not `jacl_i32_val()` (embed.c) when creating i32 values in vm.c — unity build order matters
- Macros/defines needed by both vm.c and gc_collect.c should be defined in gc.c (early in unity build order)
- `gc__struct_registry` is file-static in gc.c — not accessible from tests; use `gc_collect()` instead
