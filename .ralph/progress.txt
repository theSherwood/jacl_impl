## Codebase Patterns
- Unity build: `src/jacl.c` #includes all pipeline .c files + lib headers as a single translation unit
- JACL pipeline files in `src/`: plain .c with `#ifndef X_C` guards, no `#define X_IMPLEMENTATION` needed
- Lib modules in `lib/`: single-header convention with `#ifdef X_IMPLEMENTATION`
- Test files: `#include "test_helpers.h"` then `#include "../src/jacl.c"` — gets everything
- Arena allocator: zero-init `arena_t arena = {0}`, uses libc by default
- Test tracked allocator: `tracked_allocator` from `test/test_helpers.h`, plug into arena via `.allocator = tracked_allocator`
- Build system: `build.sh` with `TESTS=()` array entries formatted as `"path/test.c|name|optional_extra_cflags"`
- Compiler flags: `-Wall -Wextra -std=c99 -g`
- Implementation language is C (C99)
- Pipeline: src/value.c → src/string.c → src/lexer.c → src/ast.c → src/parser.c → src/bytecode.c → src/compiler.c → src/vm.c
- Private/internal functions use double-underscore prefix: `module__function_name`
- Public types use PascalCase (Token, LexResult, AstNode) or lower_t for system-level (arena_t)
- Public functions use module_verb_noun pattern (lexer_lex, arena_alloc, parser_parse)
- Constants and macros use ALL_CAPS (TOKEN_EOF, JACL_TAG_NIL)
- Test functions are `static int test_name(void)` returning 0=fail, 1=pass
- Test main() uses table-driven pattern: array of {name, fn} structs, iterates and counts pass/fail
- Memory leak check pattern: setup() -> exercise -> teardown() -> ASSERT(check_no_leaks()) -> TEST_PASS()
- Tests grouped by US-XXX story comments in the test table
- Bare word semantics change (M6): bare words at statement position desugar to zero-arg calls — existing tests using `{ yes }` must be updated to `{ "yes" }` for string-literal blocks
- $var semantics change (M6): `$var` at statement position desugars to `[$var]` (zero-arg call) — tests using `{ $x }` to return non-callable values must use `{ [+ $x 0] }` or similar expression
- To distinguish TOKEN_WORD (bare word) from TOKEN_STRING (quoted) in parser, save `parser__peek(p)->type` before calling `parser__parse_expr()` since both produce AST_LIT_STRING

## 2026-02-20 - US-002
- What was implemented: Backslash line continuation in lexer — `\` followed by `\n` or `\r\n` is consumed as whitespace (no token emitted), with line/col tracking updated
- Files changed: src/lexer.c, test/test_lexer.c
- **Learnings for future iterations:**
  - The backslash continuation check must go BEFORE the operator section in lexer_lex(), since `\` is in lexer__is_operator_char — if not intercepted first, it would be consumed as part of an operator token
  - Implementation peeks at `lex.source[lex.pos + 1]` to check the character after `\` without advancing, then only consumes if it's a newline
  - String escape handling is completely separate (in lexer__lex_string_body via lexer__handle_escape) so no interference
  - All 99 lexer tests pass, 36 test suites pass — no regressions

## 2026-02-20 - US-004
- What was implemented: Bare words at statement position now desugar to zero-arg command calls — `exit` on its own line becomes `AST_COMMAND { head: "exit", args: [], arg_count: 0 }`
- Files changed: src/parser.c, test/test_parser.c, test/test_compiler.c, test/test_integration.c, test/test_m4.c, test/test_m5.c
- **Learnings for future iterations:**
  - Implementation: save `parser__peek(p)->type` as `head_token_type` before `parser__parse_expr()`, then check `head_token_type == TOKEN_WORD` in the `args.count == 0` branch
  - Only TOKEN_WORD triggers wrapping — TOKEN_STRING (quoted), TOKEN_INT, TOKEN_FLOAT, blocks, and bracketed commands are NOT wrapped
  - This change has broad downstream impact: existing tests that used bare words inside blocks as string values (`{ yes }`, `{ no }`, `abcdefgh`) must be quoted (`{ "yes" }`, `"abcdefgh"`)
  - Affected test files: test_compiler (2 heap-string tests), test_integration (1 deliberate-error test), test_m4 (truthy/falsy), test_m5 (string equality/ordering/comparison)
  - Roundtrip tests still pass because bare-word AST_COMMAND pretty-prints as `[word]` which re-parses identically
  - All 36 test suites pass after updates

## 2026-02-20 - US-005
- What was implemented: $var at statement position now desugars to zero-arg command call — `$fn` on its own line becomes `AST_COMMAND { head: AST_VAR_REF("fn"), args: [], arg_count: 0 }`
- Files changed: src/parser.c, test/test_parser.c, test/test_compiler.c, test/test_integration.c, test/test_m4.c
- **Learnings for future iterations:**
  - Implementation: extended the existing `head_token_type == TOKEN_WORD` condition to `|| head_token_type == TOKEN_VAR` in the `args.count == 0` branch of `parser__parse_bare_command`
  - Broad downstream impact (like US-004): `{ $x }` patterns where $x holds a non-callable value (int, bool) now try to call it, causing runtime errors
  - Fix pattern for non-callable $var in blocks: use expression that evaluates to the value, e.g., `{ [+ $n 0] }` instead of `{ $n }`
  - $true/$false/$nil at top level also break — test rewrites use these as arguments inside commands (e.g., `[if $true { ... }]`)
  - `def f $greet` correctly binds f to the greet closure (via VAR_REF arg), while `def f greet` binds f to the string "greet"
  - All 36 test suites pass after updates
