## Struct Types — User-defined compound value types for JACL

Progress log for ralph/struct-types branch.

## Codebase Patterns
- Build and test with `bash build.sh` from project root
- JACL proc names must be <= 7 bytes (inline string limit). Use short names.
- `==` is the equality operator (not `=`)
- .jacl integration tests use `# mode: concurrent` and `# expect:` headers
- test files include `../src/jacl.c` directly (unity build pattern)
- Pre-existing compiler warnings in hamt.h, rrb_vec.h are expected — only check for new warnings
- GCHeader is 8 bytes: epoch(u32) + mark:1/gen:1/survive_count:2/_reserved:4 (bitfields) + obj_type(u8) + alloc_total(u16)
- When adding fields to WorkerThread, must update ALL test files' rt_test__init_no_threads helpers
- Bare `$var` in JACL is a value read (not a zero-arg call as of 16ebe58)
- CPS mode effective recursion limit ~65 iterations (VM_STACK_MAX=256)
- When adding new AST node types: must add explicit case in compiler__compile_node (no default), but analysis switches have default: cases
- realpath() available via platform.h (<stdlib.h>) — use for canonical path resolution in module system
- compiler__compile_module() is the entry point for compiling dependency modules; shares ModuleCache + ImportStack with importer
- Module exports are populated from compiler's global_arities after compilation, excluding underscore-prefixed names
- Typed proc syntax: `proc i64 add [i64 a i64 b]` — return type AFTER `proc`, not before
- TOKEN_DEFSTRUCT is a keyword token recognized by the lexer (like TOKEN_USE)
- AST_DEFSTRUCT node stores: name, field_names[], field_types[] (as string pairs)
- defstruct parsing: `defstruct Name [field :type] ...` — each field is a bracket pair with colon-prefixed type
- The `:type` annotation lexes as TOKEN_OPERATOR (colon added as operator char in US-002); `:i32` becomes `:` (TOKEN_OPERATOR) + `i32` (TOKEN_WORD)
- StructTypeRegistry holds up to 32 struct defs with C-ABI layout (field offsets, sizes, alignment)
- Struct names are registered in global_arities with type=TYPE_STRUCT and arity=field_count (for constructor)
- compiler__resolve_type() checks both built-in types and struct registry — use it instead of is_type_keyword() when struct names should be valid
- JACL_TAG_STRUCT is 0x12; JaclStruct is {type_idx, _pad, data[]} heap object (OBJ_STRUCT)
- OP_STRUCT_NEW takes uint16_t struct_type_index operand; pops N fields, allocates, pushes struct val
- Struct constructor in compiler intercepts struct names in compile_command BEFORE the dynamic call fallback
- VM.struct_registry and gc__struct_registry (void*) must be set for runtime struct ops and GC tracing
- Struct fields stored in C-ABI layout: i32/u32/f32 as 4 bytes, i64/u64/f64 as 8 bytes raw, str/dyn/vec/map/struct as JaclVal (8 bytes)
- In JACL, `true`/`false` are bare words (strings), not keywords. Use typed fields carefully — bool fields need $true/$false (var refs)
- CompileResult and ProgramResult carry struct_registry pointer to VM; jacl_run and jacl_exec_program wire it
