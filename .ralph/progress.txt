## Codebase Patterns
- `grapheme_find_safe_split` in `unicode.h` uses both fast backward-walk (Extend/ZWJ/SpacingMark check) and full UAX #29 verification via `unicode_grapheme_prev`/`unicode_grapheme_next` for complex clusters (RI pairs, ZWJ emoji)
- `rope_from_str` in `rope.h` uses `grapheme_find_safe_split` to ensure leaf boundaries never split grapheme clusters
- Test files in `lib/sum_tree/` use `#include "../../test/test_helpers.h"` for the correct relative path (not `../test/`)
- `TEST_PASS()` returns 1 (pass), ASSERT macros return 0 (fail). Main should use `if (tests[i]()) pass++; else fail++;` pattern
- Pre-existing compile failures: `segment_array`, `sum_tree`, `utf8`, `rope`, `nfa`, `nfa_rope` (wrong include path `../test/test_helpers.h`)
- Including `rope.h` in unity build requires `#define STREE_ALLOCATOR {libc_alloc, libc_realloc, libc_free, NULL}` before include (avoids C99 static initializer issue with `get_libc_allocator()` function call)
- JaclRopeString struct in string.c must be defined BEFORE unified string API functions (jacl_string_len etc.) since they reference it
- GC finalization: `gc__finalize_dead()` in gc_collect.c handles rope RC release before sweep zeroes dead objects — must be called in all 3 sweep paths
- `jacl_utf8_validate()` uses `utf8_decode` loop + surrogate check (utf8_decode doesn't reject surrogates on its own)
- `jacl_nfd_normalize()` returns input pointer when already NFD (no-copy fast path); uses stack buffer for small output, malloc for large
- NFD normalization can expand byte length (e.g., U+00E9 2 bytes NFC → 3 bytes NFD) — tier threshold must use post-NFD length
- `jacl_string_new()` is the unified constructor: validate → NFD normalize → tier route (0-7 inline, 8-128 flat, 129+ rope)
- Arena for intern table in tests: `arena_t arena = { .allocator = tracked_allocator };` (NOT `arena_init()`)
- OP_CONCAT for large results (>128 bytes): convert operands to ropes, use `rope_concat()` for O(log n) structural sharing
- Concat of two NFD strings is still NFD — `unicode_is_nfd()` fast path handles this inside `jacl_string_new()`
- Adding a new opcode to the `OpCode` enum in `bytecode.c` shifts all subsequent values — must update `test/test_bytecode.c` hardcoded opcode values
- Compiler builtin registration pattern: `compiler__head_matches(head, "name", len)` + arity check + `compiler__emit_byte(c, OP_XXX, line)`
- `jacl_grapheme_nth(data, len, n, &start, &end)` in `string.c` — finds byte range of Nth grapheme cluster in flat data; reusable for index and slice
- VM intern table: `vm->intern_table` (pointer to JaclInternTable), NOT `&vm->strings`
- `unicode_grapheme_byte_offset(data, len, n)` returns byte offset of Nth grapheme (or len if past end) — preferred over `jacl_grapheme_nth` for range operations like slice
- `rope_slice_by_graphemes(r, offset, count)` handles grapheme-based rope slicing with edge-case handling (empty/out-of-range → empty rope)
- JACL negative integer syntax: `[- 0 1]` for -1 — no unary minus on literals
- OP_CONCAT handles all 9 tier combos generically via `jacl_string_data()` + `jacl_string_byte_len()` — no per-combo specialization needed
- For flat concat results, `jacl_intern()` always computes grapheme_len from scratch via `unicode_grapheme_count()` — handles combining-at-junction correctly
- For rope concat results, `rope_concat()` (US-002) handles grapheme boundary invariant automatically
