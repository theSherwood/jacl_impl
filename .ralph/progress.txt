## Codebase Patterns
- Parser desugaring: `name = val` → `[def name val]`, `name : val` → `[mut name val]`, `name :: val` → `[set name val]`. Operator forms handled in `parser__parse_bare_command()`.
- New opcodes: add to enum in bytecode.c BEFORE OP_HALT, add name in `bytecode__opcode_name()`, add VM handler in vm.c dispatch switch, update test_bytecode.c enum value assertions.
- Compiler builtins: handled in `compiler__compile_command()` via `compiler__head_matches(head, "name", len)` pattern.
- AST_COMMAND for patterns: when `def [a b c] expr` is written in keyword form, `[a b c]` parses as AST_COMMAND with head=first-element, args=remaining-elements. Compiler detects and converts.
- Tests: e2e tests use `jacl_run()` with PrintCapture helper. Pattern: `run_capture(src, &cap)` returns VMResult, check cap.buf for output.
- Locals are stack positions: `compiler__add_local()` just records metadata, the value must already be on the stack at the right position.
- Mut locals use cells: OP_MAKE_CELL wraps top-of-stack, creating a mutable reference. Access via OP_GET_CELL_LOCAL/OP_SET_CELL_LOCAL.
- Globals (scope_depth==0): use OP_DEF_GLOBAL with name index constant. OP_DEF_GLOBAL pops value, pushes nil.
- OP_DESTRUCTURE_VEC encoding: `count (uint8), skip_mask (uint8)`. skip_mask bit i = wildcard at position i (not pushed).
- OP_DESTRUCTURE_VEC_REST encoding: `count (uint8)`. Pushes N positional elements + 1 rest vector.
- OP_DESTRUCTURE_NAMED_REST encoding: `count (uint8), N x uint16_t const_idx`. Pops struct/map, pushes N explicit fields + 1 rest map.
- Compile errors return VM_RUNTIME_ERROR from jacl_run() — no separate VM_COMPILE_ERROR value exists.
- Vectors print as `[vec 1 2 3]` (with `vec` prefix); empty vector prints as `[vec]`.
- Map iteration API: `jacl_map_iter_init()`, `jacl_map_next_leaf()`, `jacl_map_key_from_leaf()`, `jacl_map_value_from_leaf()`.
- Keyword form `[def [a b c] expr]` parses inner `[a b c]` as AST_COMMAND. Rest pattern `..name` in keyword form is NOT supported (only operator form `[a ..rest] = expr` works for rest patterns).
- Spread-all `{..}` is a compiler-driven feature: parser sets `spread_all` flag on AST_DESTRUCTURE_NAMED, compiler expands field list from StructTypeRegistry. Requires known struct type (compile error on dyn).
- `vm__struct_read_field` needs `&vm->heap` (not NULL) in OP_DESTRUCTURE_NAMED/REST handlers so i64/u64/f64 fields produce proper boxed JaclVal for globals/dyn contexts.
- Global scope `dyn d = $p` still infers struct type (effective_type from RHS). To test with true dyn, use a proc with `dyn` parameter.

- **Learnings for future iterations:**
  - Spread uses a side buffer `vm->spread_counts[32]` instead of encoding counts on the stack, to keep the stack layout clean for call dispatch.
  - Two compilation paths: OP_FOLD_SPREAD for known binary builtins (avoids call overhead), OP_CALL_SPREAD for everything else.
  - Generic spread call must resolve head the same way as normal call path: for AST_LIT_STRING heads, look up as local/global variable to get the closure, not push as string literal.
  - OP_FOLD_SPREAD format: `uint8_t op_id, uint8_t fixed_args, uint8_t num_spreads`. op_id: 0=add, 1=sub, 2=mul, 3=div.
  - OP_CALL_SPREAD format: `uint8_t fixed_args, uint8_t num_spreads`.
