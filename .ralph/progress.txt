## M16 — GC/Concurrency Hardening Phase 3

Progress log for ralph/gc-concurrency-hardening-3 branch.

## Codebase Patterns
- Build and test with `bash build.sh` from project root. Individual test files compile via `gcc -Wall -Wextra -std=c99 -g test/test_gc.c -o /tmp/test_gc`
- JACL proc names must be <= 7 bytes (inline string limit). Use short names: `bump`, `trash`, `batch`, `loop`, `run`, etc.
- `while` loops with `set` don't work correctly inside spawned CPS closures (concurrent mode). Use tail recursion instead.
- .jacl integration tests use `# mode: concurrent` and `# expect:` headers. Test harness does exact string comparison on output.
- test_gc.c includes `../src/jacl.c` directly (unity build pattern) — no separate .o linking needed
- GCHeader is 8 bytes: uint32_t epoch + uint8_t mark + uint8_t obj_type + uint16_t alloc_total
- GC_BLOCK_SIZE = 65536 (64KB), GC_LINE_SIZE = 128, GC_LINES_PER_BLOCK = 512
- Tests use BlockPool + ThreadHeap directly; some tests use VM via `vm_init(&vm, &arena)`
- Pre-existing compiler warnings in hamt.h, rrb_vec.h, etc. are expected — only check for new warnings from changed files
- `gc__emergency_gc_fn` is `__thread` — clear it in tests using raw BlockPool/ThreadHeap to avoid stale callbacks from prior VM tests
- `gc_sweep_concurrent` watermark: use `UINT32_MAX` to sweep all objects; `0` makes everything immune (epoch >= 0 always true)
- gc_sweep_concurrent signature: (ThreadHeap*, GCBlock *skip, uint32_t watermark, uint8_t mark, BlockPool *pool). Pass pool=NULL in tests that don't need block recycling
- gc_sweep_concurrent is called from 3 places: gc_concurrent_collect (runtime.c), test_runtime.c, test_m12.c — all need updating when signature changes
- runtime__push_inbox and runtime__setup_call must be defined before all functions that call them (C declaration order in unity build)

## 2026-03-04 - US-003
- Expanded the Phase 3 memcpy comment in gc_sweep_concurrent (gc_collect.c) to cover ARM/RISC-V weakly-ordered analysis
- Documented: one-directional invariant (OCCUPIED->FREE only), Phase 1 zeroing guarantee, torn byte read analysis for wide stores on ARM/AArch64, and TSan suppression guidance
- Key insight: torn bytes from wide stores clearing 0x01->0x00 can only produce non-zero intermediate values, which gc__find_free_run treats as OCCUPIED (harmless)
- Files changed: src/gc_collect.c
- **Learnings for future iterations:**
  - gc__find_free_run checks `!= GC_LINE_FREE` (i.e., `!= 0x00`), so any non-zero byte is treated as OCCUPIED — this is the key property that makes torn reads safe
  - Line map values are only 0x00 (FREE) or 0x01 (OCCUPIED) — no other values exist in the protocol
