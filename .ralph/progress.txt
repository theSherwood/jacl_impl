## Codebase Patterns
- Suspension operations (yield, await, parallel, race) are AST_COMMAND nodes with string heads — match by comparing head->data.lit_string.value
- Nested proc/spawn definitions are separate closure scopes — do NOT recurse into them during analysis
- The existing `analyze__walk_body` and `ast__contains_suspension` follow identical recursion patterns — new analysis passes should mirror their structure
- Use `memset(&struct, 0, sizeof(struct))` for struct initialization in this codebase
- Tests use `compile_source()` helper + tracked_allocator pattern from test_helpers.h
- Build with `bash build.sh` — compiles all test files in parallel then runs them sequentially
- Destructuring has 4 AST forms: AST_DESTRUCTURE_VEC, AST_DESTRUCTURE_NAMED, AST_COMMAND (bracket keyword form), AST_BLOCK (curly keyword form) — handle all 4 when extracting binding names
- `def`/`mut` support typed form with 3 args: [def type name value] — name is at args[1] when argc==3
- Named procs (`proc name {params} {body}`) create a local binding for the proc name in the enclosing scope — extract but don't recurse into body
- `compiler__analyze_suspensions` takes (body, param_names, param_count) — params are placed first in the StateLayout
- State machine objects: `gc_alloc_state_machine(heap, field_count)` returns tagged JaclVal; access via `jacl_as_state_machine(val)`; fields at `sm->fields[i]`, resume at `sm->resume_point`
- New opcodes go before OP_HALT (always last); debug names are in `bytecode__opcode_name()` switch; update test_bytecode.c enum assertions when adding opcodes
- SM function convention: state machine object lives in frame slot 0 (`frame->stack_base + 0`), resume value in slot 1
- SM dispatch table: `compiler__emit_sm_dispatch_table(c, suspension_count, line)` emits chained OP_GET_RESUME_POINT + OP_EQ + OP_JUMP_IF_FALSE + OP_JUMP checks; backpatch via `c->sm_dispatch.label_patches[i]`; resume_point 0 = initial entry (falls through), 1..N = after suspension points
- OP_GET_RESUME_POINT / OP_SET_RESUME_POINT: no operands, read/write `sm->resume_point` as i32 from state object in frame slot 0
- OP_YIELD_SM: pops yielded value, stores in vm->yield_value, sets vm->yield_continuation = JACL_NIL, returns VM_YIELD — no continuation closure needed
- SM yield sequence: compile value → OP_CONST(resume_id) + OP_SET_RESUME_POINT → OP_YIELD_SM → [resume label] → OP_NIL (yield expr result for check_error)
- SM variable resolution: when `c->sm_analysis` is set, AST_VAR_REF checks state layout first via `sm__find_field()` before falling through to normal local resolution
- SM def/mut: when `c->sm_analysis` is set, writes value to state field via OP_SET_STATE_FIELD instead of creating a stack local; no cells needed for mut in SM mode
- SM set/`::`: when `c->sm_analysis` is set, resolves to OP_SET_STATE_FIELD for state layout names before checking locals; MUST emit OP_NIL after OP_SET_STATE_FIELD so check_error has a value to consume
- SM while loops: normal while compilation (OP_LOOP backward jump) works in SM mode — no special handling needed; all variables in state object survive across yields; dispatch table jumps directly into loop body after resume
- SM generator closure: `param_count = 2` (internal __sm, __rv), `min_args = user_param_count` (for call-site arity checks), `sm_field_count = state_layout.field_count`
- OP_CHECK_ERROR pops the top-of-stack value if it's NOT an error — this is how statement results are cleaned up between statements in a block
- `arena_alloc` zero-initializes memory (`memset(ptr, 0, size)`) — no need to explicitly zero-init struct fields after arena allocation
- OP_CLOSURE copies template fields one by one — when adding new JaclClosure fields, MUST also add the copy in OP_CLOSURE (vm.c ~line 1700)
- SM generators at call site: OP_CALL detects `closure->is_sm_compiled`, allocates OBJ_STATE_MACHINE, copies args to SM fields, stores on `stream->state_machine`
- SM stream pull: check `!jacl_is_nil(stream->state_machine)` to detect SM generator; call `sm_closure(state_obj, nil)` — same call for both PENDING and CONSUMED states
- JaclStream has `state_machine` field (JaclVal) — traced by GC in gc_collect.c OBJ_STREAM case
- `[print ...]` appends a trailing `\n` — test assertions must account for it
- SM if-statements: NO special handling needed — normal if compilation (OP_JUMP_IF_FALSE/OP_JUMP) + SM yield + dispatch table compose correctly for arbitrary nesting
