## M14 — GC/Concurrency Hardening

Progress log for ralph/gc-concurrency-hardening branch.

## Codebase Patterns
- RuntimeTask gc_root/gc_root2 must always be initialized (JACL_NIL if unused) — test code that creates RuntimeTask manually must set both fields
- GC root scanning has three paths: currently_executing, deque snapshot, and inbox — all three must be updated in sync
- Tests that create RuntimeTask manually must be updated when the struct changes
- Use `rt_test__init_no_threads` / `rt_test__destroy_no_threads` for unit tests that don't need real worker threads
- `rt_test__ms_contains` destructively drains the mark stack but restores entries — safe for multiple checks on same stack
- `test__compile` + `rt_run_to_completion` does NOT register user procs in worker VMs — parallel body closures that call user procs will hang. Use `.jacl` tests with `# mode: concurrent` for tests that need proc calls in parallel bodies (the harness copies env to workers)
