## FFI & Embedding API (M17) — C embedding API for JACL

Progress log for ralph/ffi-embedding branch.

## Codebase Patterns
- Build and test with `bash build.sh` from project root
- JACL proc names must be <= 7 bytes (inline string limit). Use short names.
- `==` is the equality operator (not `=`)
- .jacl integration tests use `# mode: concurrent` and `# expect:` headers
- test files include `../src/jacl.c` directly (unity build pattern)
- Pre-existing compiler warnings in hamt.h, rrb_vec.h are expected — only check for new warnings
- GCHeader is 8 bytes: epoch(u32) + mark:1/gen:1/survive_count:2/_reserved:4 (bitfields) + obj_type(u8) + alloc_total(u16)
- When adding fields to WorkerThread, must update ALL test files' rt_test__init_no_threads helpers
- Bare `$var` in JACL is a value read (not a zero-arg call as of 16ebe58)
- CPS mode effective recursion limit ~65 iterations (VM_STACK_MAX=256)
- When adding new AST node types: must add explicit case in compiler__compile_node (no default), but analysis switches have default: cases
- realpath() available via platform.h (<stdlib.h>) — use for canonical path resolution in module system
- embed.c cannot #include jacl.h directly — redefinition conflicts with internal types. Forward-declare JaclVM, JaclConfig etc. in embed.c instead
- JaclVM_s wraps: VM (internal), arena_t (owns memory), JaclInternTable (persistent across evals), max_handles, last_error
- compiler__compile_module() is the entry point for compiling dependency modules; shares ModuleCache + ImportStack with importer
- Module exports are populated from compiler's global_arities after compilation, excluding underscore-prefixed names
- Typed proc syntax: `proc i64 add [i64 a i64 b]` — return type AFTER `proc`, not before
- TOKEN_DEFSTRUCT is a keyword token recognized by the lexer (like TOKEN_USE)
- StructTypeRegistry holds up to 32 struct defs with C-ABI layout (field offsets, sizes, alignment)
- Struct names are registered in global_arities with type=TYPE_STRUCT and arity=field_count (for constructor)
- JACL_TAG_STRUCT is 0x12; JaclStruct is {type_idx, _pad, data[]} heap object (OBJ_STRUCT)
- VM.struct_registry and gc__struct_registry (void*) must be set for runtime struct ops and GC tracing
- gc.c is included BEFORE compiler.c in unity build, so gc__struct_registry must be void*
- defstruct emits only OP_NIL at runtime — no OP_DEF_GLOBAL. Struct constructors exist only at compile time
- The OP_HALT value changes when new opcodes are added — update test_bytecode.c opcode_enum test
- VM is single-threaded for external callers. NxM scheduler owns internal threading.
- Public embed API constructors use `_val` suffix (jacl_i32_val) to avoid collision with internal names (jacl_i32)
- Strings ≤7 bytes are inline (no heap needed); >7 bytes go through jacl_intern to GC heap
- VM struct has gc_handle_slots/gc_handle_count fields for GC root scanning — set by embedding layer, scanned by gc_mark and gc_mark_minor
- Handle API uses `_val` suffix (jacl_handle_new_val) and EmbedJaclHandle type to avoid collision with jacl.h declarations

- **Learnings for future iterations:**

  - Internal value constructors (jacl_i32, jacl_bool etc.) already exist in value.c — public API uses _val suffix to avoid collision
  - No include/ directory existed before this story

## 2026-03-11 - US-002
- Implemented `jacl_vm_new`, `jacl_vm_new_ex`, `jacl_vm_free` in `src/embed.c`
- `JaclVM_s` struct wraps internal VM, arena_t, JaclInternTable, and max_handles
- `jacl_vm_new()` delegates to `jacl_vm_new_ex(NULL)` with default 1024 handles
- `jacl_vm_new_ex` applies JaclConfig: initial_heap_size → gc_threshold (clamped), max_heap_size → block_pool.max_blocks, max_handles stored for future handle API
- `jacl_vm_free(NULL)` is safe no-op
- Multiple VMs coexist independently (separate arenas, block pools, heaps)
- Files changed: src/embed.c (new), src/jacl.c (added embed.c include), test/test_embed.c (new), build.sh (added embed test)
- **Learnings for future iterations:**
  - Cannot include jacl.h from embed.c — JaclType and JaclVal typedefs conflict with internal definitions. Must forward-declare JaclVM, JaclConfig in embed.c
  - Functions in embed.c must be `static` (unity build pattern)
  - JaclVM_s struct definition is in embed.c — all future embedding API functions access internal VM via `jvm->vm`
  - Intern table is initialized once per JaclVM and persists across evals (unlike jacl_run which creates a local one)

## 2026-03-11 - US-003
- Implemented `jacl_eval`, `jacl_eval_file`, `jacl_is_error` (reuses internal), `jacl_error_message_str` in `src/embed.c`
- `jacl_eval` does lex → parse → compile → exec, using persistent intern table and preserving env (globals) across calls
- Handles both normal and CPS-transformed code paths (mirroring `jacl_run`)
- Error values use existing `JACL_FLAG_ERROR` (bit 61) on JACL_NIL — no new tag needed
- Error messages stored on `JaclVM_s.last_error` (arena-allocated)
- `jacl_eval_file` reads file into arena buffer, then delegates to `jacl_eval`
- Added 10 tests: basic eval, parse error, runtime error, globals persist, independent VMs, non-error check, error message null for non-error, eval_file, file not found, compile error
- Files changed: src/embed.c, test/test_embed.c
- **Learnings for future iterations:**
  - JACL already has `jacl_is_error` / `jacl_set_error` in value.c using JACL_FLAG_ERROR (bit 61) — don't create a separate error tag
  - Bare identifiers like `nil`, `true`, `false` are in VM env but NOT compiler-known — can't eval "nil" directly, must use `$nil` or expressions
  - `jacl_eval` must reset stack_top and frame_count before execution but NOT touch env (preserves globals)
  - embed.c error message function named `jacl_error_message_str` to avoid collision with any future internal `jacl_error_message`

- Extractors: `jacl_as_i32_val`, `jacl_as_i64_val`, `jacl_as_u32_val`, `jacl_as_u64_val`, `jacl_as_f32_val`, `jacl_as_f64_val`, `jacl_as_bool_val`, `jacl_as_cstr_val`

- Added 16 tests covering all constructors, extractors, type queries, inline/heap strings, round-trip through eval
- Files changed: src/embed.c, test/test_embed.c
- **Learnings for future iterations:**
  - Public API functions use `_val` suffix to avoid collision with internal constructors (e.g. `jacl_i32_val` vs `jacl_i32`)
  - Strings ≤7 bytes use inline encoding (no heap allocation); longer strings go through `jacl_intern` to GC heap
  - `jacl_as_cstr_val` must copy string data to arena with null terminator since neither inline nor heap strings are null-terminated
  - Heap-allocated types (i64, u64, f64) need `ThreadHeap*` from `jvm->vm.heap` — can't be created without a VM
  - `EmbedJaclType` enum in embed.c mirrors `JaclType` in jacl.h — both inline and heap strings map to EMBED_TYPE_STR

  - UINT32_MAX sentinel for invalid handle index works well for error signaling
