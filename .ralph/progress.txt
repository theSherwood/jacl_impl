# Ralph Progress Log
Started: Sat Apr 11 15:40:27 UTC 2026

## Codebase Patterns
- Unity build: all .c files are `#include`d into `src/jacl.c`; system headers (stdio, stdlib via platform.h) are available everywhere
- Build/test: `bash build.sh --parallel` runs all tests; `--test=NAME` filters to a single test
- Inline strings are 7-byte max (NaN-boxed payload); longer strings must use `jacl_intern` (heap-interned, pointer-stable) or `jacl_rope_string_create`
- The `concurrent_intern` test is flaky (race condition, off-by-one in counts) — not a real failure
- The `m13` test crashes with a pthread assertion (`__pthread_tpp_change_priority`) — pre-existing, not related to macro-eval work
- `vm_exec` must reset `vm->stack_top = 0` — staged macro expansion calls `jacl_ctx_run_closure` on the same VM during compilation, leaving stale stack values
- `jacl.h` VM struct must mirror `vm.c` VM struct exactly — mismatched fields cause struct layout offset bugs in test binaries (e.g., missing `macro_scope_mark`)
- Compiler uses `compiler__name_val` helper for all name construction: <=7 inline, 8-128 interned, >128 rejected
- Analysis functions (suspension analysis, capture analysis, etc.) now accept heap/intern_table params for name construction
- `abort()` is available via `lib/platform/platform.h` which includes `<stdlib.h>`

Thread: (inline)
- Added `use_staged_syntax_quote` flag to `ExpandState` and `jacl_context_t`; plumbed through `compiler_compile` → `Compiler.use_staged_syntax_quote`
- Implemented `syntax__compile_sq_node` recursive function in compiler.c that emits `OP_SYNTAX_OP` make-syntax bytecode:
  - AST_LIT_INT → push i32 → subop 7 (make-syntax lit-int)
  - AST_LIT_FLOAT → push f32 → subop 8 (make-syntax lit-float)
  - AST_LIT_STRING → push string → subop 9 (make-syntax lit-string)
  - AST_VAR_REF → push name → subop 10 (make-syntax var-ref)
  - AST_COMMAND → recurse head, recurse args, OP_VEC, subop 11 (make-syntax command)
  - AST_BLOCK → recurse commands, OP_VEC, subop 12 (make-syntax block)
  - AST_UNQUOTE → compile inner expression normally (must produce syntax JaclVal)
  - AST_UNQUOTE_SPLICING → handled at parent level with OP_VEC_PUSH/OP_VEC_CONCAT
  - AST_SYNTAX_QUOTE (nested) → emit as constant via syntax_from_ast
  - Other nodes → fallback to constant via syntax_from_ast
- Gated new path in `AST_SYNTAX_QUOTE` case: checks `c->use_staged_syntax_quote`
- Added 4 integration tests: `test_staged_sq_literal`, `test_staged_sq_unquote`, `test_staged_sq_splice`, `test_staged_sq_nested`
- Files changed: src/compiler.c, src/jacl.h, src/vm.c, test/test_integration.c
- **Learnings for future iterations:**
  - Command heads (like `+`) parse as `AST_LIT_STRING`, not `AST_VAR_REF` — the head in a syntax-quote produces `SYNTAX_LIT_STRING`
  - `OP_VEC_PUSH` stack order: [vec, elem] → pops elem first, then vec → pushes new_vec
  - `OP_VEC_CONCAT` stack order: [a, b] → pops b first, then a → pushes a++b
  - The staged path and legacy path produce structurally identical syntax objects — the difference is only in how the bytecode constructs them
