## Codebase Patterns
- WASM build: `EM_CACHE=/tmp/emscripten_cache bash build_wasm.sh` — produces build_wasm/jacl.{js,wasm}
- WASM test: `node test/test_wasm.mjs` — requires build_wasm/ to exist
- JaclVal is uint64_t: Emscripten needs `-s WASM_BIGINT=1` for correct 64-bit passing; use direct `_function` access in JS, not cwrap
- `JACL_EMBED_FN` macro in embed.c: `static` (native unity build) or `EMSCRIPTEN_KEEPALIVE` (WASM); use for all public API functions
- `JACL_THREAD_LOCAL` macro in platform.h replaces raw `__thread` — empty under Emscripten (single-threaded)
- Build and test with `bash build.sh` from project root
- JACL proc names must be <= 7 bytes (inline string limit). Use short names.
- `==` is the equality operator (not `=`)
- .jacl integration tests use `# mode: concurrent` and `# expect:` headers
- test files include `../src/jacl.c` directly (unity build pattern)
- Pre-existing compiler warnings in hamt.h, rrb_vec.h are expected — only check for new warnings
- GCHeader is 8 bytes: epoch(u32) + mark:1/gen:1/survive_count:2/_reserved:4 (bitfields) + obj_type(u8) + alloc_total(u16)
- When adding fields to WorkerThread, must update ALL test files' rt_test__init_no_threads helpers
- Bare `$var` in JACL is a value read (not a zero-arg call as of 16ebe58)
- CPS mode effective recursion limit ~65 iterations (VM_STACK_MAX=256)
- When adding new AST node types: must add explicit case in compiler__compile_node (no default), but analysis switches have default: cases
- realpath() available via platform.h (<stdlib.h>) — use for canonical path resolution in module system
- embed.c cannot #include jacl.h directly — redefinition conflicts with internal types. Forward-declare JaclVM, JaclConfig etc. in embed.c instead
- JaclVM_s wraps: VM (internal), arena_t (owns memory), JaclInternTable (persistent across evals), max_handles, last_error
- compiler__compile_module() is the entry point for compiling dependency modules; shares ModuleCache + ImportStack with importer
- Module exports are populated from compiler's global_arities after compilation, excluding underscore-prefixed names
- Typed proc syntax: `proc i64 add [i64 a i64 b]` — return type AFTER `proc`, not before
- TOKEN_DEFSTRUCT is a keyword token recognized by the lexer (like TOKEN_USE)
- StructTypeRegistry holds up to 32 struct defs with C-ABI layout (field offsets, sizes, alignment)
- Struct names are registered in global_arities with type=TYPE_STRUCT and arity=field_count (for constructor)
- JACL_TAG_STRUCT is 0x12; JaclStruct is {type_idx, _pad, data[]} heap object (OBJ_STRUCT)
- VM.struct_registry and gc__struct_registry (void*) must be set for runtime struct ops and GC tracing
- gc.c is included BEFORE compiler.c in unity build, so gc__struct_registry must be void*
- defstruct emits only OP_NIL at runtime — no OP_DEF_GLOBAL. Struct constructors exist only at compile time
- The OP_HALT value changes when new opcodes are added — update test_bytecode.c opcode_enum test
- VM is single-threaded for external callers. NxM scheduler owns internal threading.
- Public embed API constructors use `_val` suffix (jacl_i32_val) to avoid collision with internal names (jacl_i32)
- Strings ≤7 bytes are inline (no heap needed); >7 bytes go through jacl_intern to GC heap
- VM struct has gc_handle_slots/gc_handle_count fields for GC root scanning — set by embedding layer, scanned by gc_mark and gc_mark_minor
- Handle API uses `_val` suffix (jacl_handle_new_val) and EmbedJaclHandle type to avoid collision with jacl.h declarations
- Native fn dispatch uses callback pattern: VM stores `call_native` function pointer + `native_fn_ctx` (JaclVM*), embed.c provides the implementation
- Native fn arity array is mirrored on VM struct for fast OP_CALL validation without crossing the embed boundary
- embed__register_native() adds native fn to registry AND injects into VM env as a global — compiler sees it as existing global
- JACL_TAG_NATIVE_FN is 0x13; payload is uint32_t index into NativeFnEntry registry
- OP_TAIL_CALL degrades to regular call for native functions (no tail optimization possible)
- jacl_eval saves/restores full VM state (stack, frames, ip, chunk) for re-entrant calls from native functions
- jacl_register_fn_val is the public API name (with _val suffix) wrapping embed__register_native
- JACL proc syntax is `proc name [params] { body }` — use `$name` to get closure value after defining
- Build env: gcc unavailable; use `CC=/usr/bin/cc -Wno-implicit-function-declaration -lpthread -lm -D_POSIX_C_SOURCE=200809L` for embed tests. `realpath` errors in compiler.c are pre-existing.

- /tmp is noexec — run build with `TMPDIR=/var/tmp` so mktemp -d creates executable test binaries: `TMPDIR=/var/tmp CC="..." bash build.sh`
- jacl_call_val sets up 1 frame (frame_count=1), vm__run exits when OP_RETURN drops frame_count to 0, result in stack[0]
- compiler_compile takes a `seed_registry` (StructTypeRegistry*) param — pass `&jvm->persistent_struct_registry` from embed to accumulate struct defs across evals; pass NULL from vm.c jacl_run
- JaclVM_s.persistent_struct_registry holds accumulated struct defs; copy cr.struct_registry back to it after each eval
- jacl_struct_new_val/get_val/set_val/type_name_val use `_val` suffix and `jvm->persistent_struct_registry` for name-based lookup (not index-based)
- JaclTrampoline_s is defined inside `#ifdef JACL_HAS_LIBFFI` with a stub in `#else`; forward-declare struct before JaclVM_s; handle pinning uses raw slot manipulation (not EmbedJaclHandle) to avoid ordering issues
- Trampoline signature format: `rettype(argtype,argtype)` — types: void, i32, i64, u32, u64, f32, f64, ptr; void only valid as return type
- Two error kinds: (1) inline error-flagged values (e.g. i32 div-by-zero) — VM_OK, no `last_error`; (2) VM_RUNTIME_ERROR (e.g. undefined var, type mismatch) — `last_error` set via `embed__make_error`
