Feature: Struct Value Types — Headerless Stack-Allocated Structs

## US-001: Arena-based struct type registry
- Replaced fixed 32-slot `StructTypeDef[]` with `StructTypeDef**` pointer array + arena allocation
- `StructTypeDef` now uses flexible array member (`StructTypeField fields[]`) — no `STRUCT_MAX_FIELDS` limit
- `StructTypeField` extracted as named typedef for reuse
- `type_idx == 0` reserved for plain dyn boxes; struct types start at 1
- Registry init/destroy helpers: `struct_registry__init()`, `struct_registry__destroy()`, `struct_registry__grow()`, `struct_registry__alloc_def()`
- Embed API: persistent registry is heap-allocated pointer, passed as seed directly (no copy-back)
- Fixed latent bugs: default `struct_type_idx = 0` was valid under old 0-based scheme but maps to reserved NULL slot under 1-based — added NULL guards in field access and destructuring, added `param_struct_idxs[]` tracking for typed proc parameters
- All `.field` access on registry entries changed to `->field` (pointer deref)
- `struct_registry__destroy` called at all exit paths in `jacl_run` and `jacl_ctx_destroy`

## 2026-04-25 - US-005: Struct field access — byte-offset addressing
- New opcodes: `OP_STRUCT_GET_INLINE` (base_slot, byte_offset, field_type), `OP_STRUCT_SET_INLINE` (same), `OP_STRUCT_MATERIALIZE` (base_slot, type_idx)
- OP_STRUCT_GET_INLINE: reads field from stack-resident inline struct via byte-offset addressing; TYPE_STRUCT variant reads additional uint16_t type_idx and materializes sub-struct to heap
- OP_STRUCT_SET_INLINE: pops value, writes to inline struct field, pushes nil
- OP_STRUCT_MATERIALIZE: converts entire inline struct to heap-allocated JaclStruct (for `print $p`, return values, etc.)
- Compiler activates inline construction (`want_inline_struct`) for struct locals in `def` handler; sets `is_inline` flag and adds padding locals for wide structs
- Field access `[. ...]` handler: Case 1 (direct var ref) and Case 2 (chained command) detect inline struct locals and emit byte-offset opcodes instead of legacy heap path
- Nested offset chaining: `$ln->start->x` accumulates byte offsets at compile time using `inline_struct_ref`, `inline_ref_base_slot`, `inline_ref_offset` compiler state
- Sub-struct field access (TYPE_STRUCT field): emits OP_STRUCT_GET_INLINE with TYPE_STRUCT + type_idx to materialize; if chained, outer handler pops materialized value and uses byte-offset instead
- AST_VAR_REF handler: inline struct locals emit OP_STRUCT_MATERIALIZE for non-field-access use
- Added `ModuleBinding` typedef and `COMPILER_MODULE_BINDINGS_MAX` to `jacl.h` (were only in `compiler.c`) to keep Compiler struct in sync
- Updated bytecode enum test values (3 new opcodes at positions 126-128, HALT now 164)
- 6 new tests: inline get basic, inline set basic, nested get with offset chaining, materialize, wide field types (Vec3), preserves other locals
- Files changed: `src/jacl.h`, `src/compiler.c`, `src/vm.c`, `src/bytecode.c`, `test/test_bytecode.c`, `test/test_compiler.c`
- **Learnings for future iterations:**
  - When Compiler struct in jacl.h is out of sync with compiler.c, tests that stack-allocate Compiler (module import tests) get memory corruption — always verify both are in sync
  - Sub-struct inline field access (TYPE_STRUCT field) must materialize to heap even if chaining is possible, because standalone use (return, print) needs a value on the stack; chaining handler pops the materialized value when it's not needed
  - `ModuleBinding` and `COMPILER_MODULE_BINDINGS_MAX` were previously only in compiler.c — added to jacl.h to keep struct layouts identical

## 2026-04-28 - US-006: Struct arguments — pass by value
- New opcode: `OP_STRUCT_COPY` — pops heap JaclStruct, allocates deep copy via gc_alloc + memcpy, pushes copy
- Compiler emits OP_STRUCT_COPY after compiling each struct-typed argument at call sites
- Condition: `arg_type == TYPE_STRUCT || expected_param_type == TYPE_STRUCT`
- For inline struct locals: OP_STRUCT_MATERIALIZE (from var ref) already creates heap copy, OP_STRUCT_COPY adds redundant but harmless second copy
- For heap struct params (received from callers): OP_STRUCT_COPY is essential — prevents shared pointer aliasing
- Chained calls (outer→inner) correctly isolate each frame's struct data
- Updated bytecode enum test values (OP_STRUCT_COPY at position 129, HALT now 165)
- 3 new tests: basic pass-by-value (mutation isolation), recursive struct chaining, chained call isolation (outer→inner→test)
- Files changed: `src/jacl.h`, `src/compiler.c`, `src/vm.c`, `src/bytecode.c`, `test/test_bytecode.c`, `test/test_compiler.c`
- **Learnings for future iterations:**
  - JACL struct field set syntax inside proc body: `. $p x 99` (top-level command, no brackets), NOT `[. $p x 99]` which causes parse errors
  - Return values from proc calls are `dyn` at compile time — use `def Point r [foo $x]` (typed def) to get struct type for further struct-typed operations
  - `jacl_as_struct` does NOT exist — use `jacl_as_struct_ptr(val)` to extract JaclStruct* from JaclVal

## 2026-04-28 - US-007: Struct returns — pass by value
- New opcode: `OP_STRUCT_STORE_INLINE` — reads heap JaclStruct from stack, de-materializes into inline (stack-resident) slots via memcpy
- Added `return_struct_idx` field to `Local` and `GlobalArity` structs — tracks struct type index for function return types
- Proc compilation: 4-arg proc syntax (`proc Point mkpt {i32 a, i32 b} { ... }`) resolves return type via `struct_registry__find` and stores `return_struct_idx`
- `return_struct_idx` propagated from locals/globals to `call_return_struct_idx` at call sites; sets `c->last_struct_idx` after call compilation
- Def handler extension: after compiling function call RHS, checks if `rhs_type == TYPE_STRUCT && c->last_struct_idx != UINT32_MAX` to post-activate inline storage
- Emits `OP_STRUCT_STORE_INLINE(base_slot, type_idx)` after adding inline local + padding locals
- VM handler: reads base_slot + type_idx, extracts JaclStruct* from heap val, zero-fills width slots, memcpy struct data, adjusts stack_top
- Updated bytecode enum test values (OP_STRUCT_STORE_INLINE at position 130, HALT now 166)
- 3 new tests: basic return (mkpt returns Point), nested calls (mkpt called with field access args), value isolation (mutation of returned copy doesn't affect original)
- Files changed: `src/jacl.h`, `src/compiler.c`, `src/vm.c`, `src/bytecode.c`, `test/test_bytecode.c`, `test/test_compiler.c`
- **Learnings for future iterations:**
  - JACL `+` operator returns `dyn` at compile time, not i32 — avoid using `+` in struct constructors when typed fields are needed; pass pre-computed i32 params instead
  - `GlobalArity` struct also lives in both `jacl.h` and `compiler.c` — must keep in sync (same as Local, Compiler)
  - `proc Type name {params} { body }` is the 4-arg proc syntax for declaring return types

## Codebase Patterns
- In JACL, `$true`/`$false` are the boolean values; bare `true`/`false` are strings
- `jacl_f64_val(vm, val)` requires a JaclVM pointer as first argument (unlike `jacl_i32_val(val)`)
- Parser tests are independent of compiler validation — only test AST structure
- `Local` and `Compiler` structs are defined in both `jacl.h` and `compiler.c` — update both when adding fields
- Bytecode enum values are tested with hardcoded integers in `test/test_bytecode.c` — update after inserting opcodes
- Test VM opcodes by constructing `BytecodeChunk` manually: `chunk_init`, `chunk_write`, `chunk_add_constant`
