## Codebase Patterns
- JACL comments use `#` not `;` — semicolons are statement separators; using `;` as a comment causes parse errors or unexpected bare-word calls
- String interpolation syntax: `$var` or `$[expr]` inside double-quoted strings — `[expr]` without `$` prefix is literal text, not interpolation
- File-based test harness: test/test_jacl_harness.c reads .jacl files from test/jacl/, parses # expect: / # expect-error: headers, runs through jacl_run with PrintCapture
- PrintCapture buffer in harness is 8192 bytes (larger than integration tests' 1024) to handle multi-line test output
- Harness uses malloc/free for file I/O (not tracked_allocator) — tracked_allocator is only for the VM arena
- Unity build: `src/jacl.c` #includes all pipeline .c files + lib headers as a single translation unit
- JACL pipeline files in `src/`: plain .c with `#ifndef X_C` guards, no `#define X_IMPLEMENTATION` needed
- Lib modules in `lib/`: single-header convention with `#ifdef X_IMPLEMENTATION`
- Test files: `#include "test_helpers.h"` then `#include "../src/jacl.c"` — gets everything
- Arena allocator: zero-init `arena_t arena = {0}`, uses libc by default
- Test tracked allocator: `tracked_allocator` from `test/test_helpers.h`, plug into arena via `.allocator = tracked_allocator`
- Build system: `build.sh` with `TESTS=()` array entries formatted as `"path/test.c|name|optional_extra_cflags"`
- Compiler flags: `-Wall -Wextra -std=c99 -g`
- Implementation language is C (C99)
- Pipeline: src/value.c → src/gc.c → src/string.c → src/lexer.c → src/ast.c → src/parser.c → src/bytecode.c → src/compiler.c → src/vm.c
- Private/internal functions use double-underscore prefix: `module__function_name`
- Public types use PascalCase (Token, LexResult, AstNode) or lower_t for system-level (arena_t)
- Public functions use module_verb_noun pattern (lexer_lex, arena_alloc, parser_parse)
- Constants and macros use ALL_CAPS (TOKEN_EOF, JACL_TAG_NIL)
- Test functions are `static int test_name(void)` returning 0=fail, 1=pass
- Test main() uses table-driven pattern: array of {name, fn} structs, iterates and counts pass/fail
- Memory leak check pattern: setup() -> exercise -> teardown() -> ASSERT(check_no_leaks()) -> TEST_PASS()
- Tests grouped by US-XXX story comments in the test table
- Bare word semantics (M6): bare words at statement position desugar to zero-arg calls — use `{ "yes" }` not `{ yes }` for string-literal blocks
- $var semantics (M6): `$var` at statement position desugars to `[$var]` (zero-arg call) — use `{ [+ $x 0] }` not `{ $x }` for non-callable values
- `def g f` binds g to the string "f", NOT the proc — use `def g $f` to capture a proc value
- Integration tests use PrintCapture pattern with `vm.print_fn`/`vm.print_ctx` — no `last_result` field on VM
- The `print` builtin appends `\n` to output
- Files sorted alphabetically for deterministic test ordering
- Collection nodes use libc malloc (not arena) — tracked_allocator won't detect leaks; will migrate to gc_alloc in US-004/US-005
- VM now owns BlockPool + ThreadHeap; vm_init initializes, vm_destroy cleans up — must call vm_destroy before arena_destroy
- Test teardown order: vm_destroy → gc_heap_destroy → gc_block_pool_destroy → arena_destroy
- Heap-allocating value constructors (jacl_i64, jacl_u64, jacl_f64 + arithmetic) live in gc.c not value.c (dependency order)
- jacl_intern takes ThreadHeap* (not arena_t*) — strings allocated on GC heap via gc_alloc(heap, OBJ_STRING, ...)
- compiler_compile takes ThreadHeap* as 4th parameter for string interning
- OP_CLOSURE allocates closure + inline upvalue array as single gc_alloc (trailing array pattern)
- OP_MAKE_CELL, OP_BOX, OP_ATOM allocate JaclMutableRef via gc_alloc(heap, OBJ_MUTABLE_REF, ...)
- Template allocator: use `{ .alloc = libc_alloc, .free = libc_free, .ctx = NULL }` compound literal (NOT `libc_allocator` which is a function call, fails as C99 static initializer)
- Must `#undef RC_ALLOCATOR` between RRB and HAMT template includes (rc.h doesn't clean up non-defaulted allocators)

## GC & Concurrency Architecture (from GC_CONCURRENCY_DESIGN.md)
- GCHeader (8 bytes) replaces RCHeader (16 bytes): { epoch, mark, obj_type, gen, _pad }
- Per-thread heaps: 64KB blocks, 512 lines × 128 bytes, Immix-style bump allocation
- Epoch-based watermark: objects at or after watermark = min(thread_epochs) are immune to collection
- Hybrid write barrier: SATB (old value) + insertion (new value) on mutable container mutation during active GC
- Mark bit alternation: current_mark toggles 0/1 each cycle (avoids clearing all marks)
- BUSY sentinel: workers publish BUSY before popping from deque, GC spins until resolved
- Grey buffer: per-thread append-only buffer, drained periodically during mark + final drain
- GC is a task on a deque — any worker can execute it; mutual exclusion via gc_running atomic CAS
- Chase-Lev deque already implemented at lib/chase_lev/chase_lev.h
- Platform atomics already at lib/platform/platform.h (ATOMIC_CAS, ATOMIC_LOAD, ATOMIC_STORE, etc.)
- Sweep criteria: marked → live; not marked + epoch >= watermark → live; not marked + epoch < watermark → reclaim
- String interning Phase 1: immortal (never collected); Phase 2 deferred (weak-reference intern table)
- Generational collection (sticky mark-bit) deferred to future PRD
- gc.c is inserted after value.c and before string.c in the unity build chain; gc_collect.c is after vm.c (needs collection types + VM struct)
- Mark/sweep code lives in gc_collect.c (not gc.c) because it needs HAMT/RRB types from collections.c and VM struct from vm.c
- GCMarkStack uses void* entries (raw payload pointers), not JaclVal — handles both tagged values and raw node pointers uniformly
- jacl_map_set takes 3 args (root, key, value) — hash computed internally, not passed separately
- GCHeader is 8 bytes: { uint32_t epoch; uint8_t mark, obj_type; uint16_t alloc_total; }
- gc_header_of(payload) returns (GCHeader*)payload - 1
- jacl_is_heap_type checks 11 tags: STRING, VECTOR, MAP, CLOSURE, BIGNUM, CELL, BOX, ATOM, I64, U64, F64
- gc_alloc(ThreadHeap* heap, uint8_t obj_type, size_t payload_size) — bump-allocates with GCHeader prepended, returns payload pointer
- ThreadHeap stores BlockPool* pointer; gc_heap_init(heap, pool) links them
- BlockPool is thread-safe (mutex); gc_block_pool_get/return for block recycling
- Allocation total aligned to 8 bytes; max single allocation = GC_BLOCK_SIZE (64KB)
- HAMT GC mode: define HAMT_GC_MODE + HAMT_GC_ALLOC(obj_type, sz) + HAMT_GC_OBJ_* before including hamt.h — replaces RC with gc_alloc, no-op ref/unref
- gc__current_heap: file-static ThreadHeap* in gc.c (unity-build visible), set before any HAMT mutation; will become __thread in US-008
- HAMT transient API requires RC (ownership checks via ref_count==1); wrapped in #ifndef HAMT_GC_MODE — unused by JACL
- Library-level HAMT tests (lib/hamt/test_hamt*.c) still use RC mode — HAMT_GC_MODE is only for jacl_map in collections.c
- jacl_map_unref is now a no-op (H_RC_UNREF(p) expands to ((void)0) in GC mode) — callers don't need to call it
- H_ALLOC_LEAF/INTERNAL/COLLISION macros abstract allocation per node type — same pattern available for RRB migration (US-005)
- RRB_VEC_GC_MODE: same opt-in pattern as HAMT — define RRB_VEC_GC_MODE + RRB_VEC_GC_ALLOC + RRB_VEC_GC_OBJ_* before including rrb_vec.h
- RRB auxiliary allocator (size tables, temp arrays) remains libc-backed even in GC mode — only node allocation routes through gc_alloc
- RRB transient API + map/filter via transient wrapped in #ifndef RRB_VEC_GC_MODE; GC-mode map/filter use persistent push_back
- rc.h no longer included by collections.c — both HAMT and RRB use GC mode
- GCHeader.alloc_total stores the full aligned allocation size (header+payload+padding) — enables object walking during sweep
- Block payload zeroed on acquisition (gc_block_pool_get memsets to 0) — alloc_total==0 is sentinel for "no object here" during sweep
- gc_sweep walks objects using alloc_total, zeros dead objects, recycles all-free blocks to pool
- gc_collect(heap, vm): mark + sweep + toggle current_mark + reset bytes_since_gc + reset needs_gc
- GC trigger: gc__bump_alloc sets heap->needs_gc when bytes_since_gc > GC_THRESHOLD; vm__run checks needs_gc at top of dispatch loop
- Forward-declare gc_collect in vm.c (before definition in gc_collect.c) to call from vm__run — valid C99 in unity build
- gc_mark scans intern table entries as roots (Phase 1: immortal strings), plus chunk constants (skip closures = arena templates)
- Closure tracing now includes chunk constants (heap i64/u64/f64 literals, skip JACL_TAG_CLOSURE entries = arena templates)
- jacl_vec_get returns jacl_vec_get_result struct with .value field — not a raw JaclVal
- vm_exec wraps top-level code in implicit closure frame (frame_count starts at 1), sets vm->top_chunk for GC root scanning
