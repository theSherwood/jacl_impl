## Codebase Patterns
- `compiler_compile` returns a `CompileResult` with a `BytecodeChunk`; to execute top-level code, wrap in a JaclClosure and call `vm_exec`, NOT `jacl_ctx_run_closure` (which expects stack_base=1 for lambda closures)
- `jacl_ctx_run_closure` is for calling proper closures (lambdas), not top-level compiled chunks
- Parse errors are detected by `parse.error_count > 0` and the first error message is found by walking `parse.nodes` looking for `AST_ERROR`
- Compile errors are detected by `cr.error_count > 0` and message is in `cr.error_message`
- Unknown command heads are NOT compile errors — they compile to proc/global calls and fail at runtime
- For compile-error tests use bad builtin arity (e.g. `[def]`) not unknown names
- `ExpandState.ctx` must be set to a valid context for macro expansion to work; if NULL, `ast_expand_macros` creates a temp context automatically
- Tests use `jacl_context_t` pattern: `jacl_ctx_new(NULL)` → use ctx→arena/heap/intern_table → `jacl_ctx_destroy`
- To run a compiled closure from within `vm__run`: save (stack_top, frame_count, ip, chunk, top_chunk), push dummy callee, set up CallFrame with stack_base above dummy, call `vm__run(vm, saved_frame_count)`, get result from stack_top-1, restore state
- `MacroEntry.is_builtin` MUST be set to false for user-defined macros; macro_table_init only zeros count, not entries
- HAMT map type is `jacl_map_node*` (from `jacl_as_ptr()`), NOT `jacl_map_root*`
- `vm__env_get`/`vm__env_set` use identity comparison (`==`) for name keys — short names (≤7 bytes) must use `jacl_inline_string`, NOT `jacl_intern`
- When compiling with a prelude map, the compiler registers keys as globals via `compiler__set_global_arity` and enforces closed-world name resolution (unresolved names → compile error)
- HAMT map iteration pattern: `jacl_map_iter_init(node)` → loop `jacl_map_next_leaf(&it)` → `jacl_map_key_from_leaf(ir.item)` / `jacl_map_value_from_leaf(ir.item)`
- Reserved prelude keys start with ':' (e.g. `:core`) and are skipped during global registration
- OpCode enum is duplicated in src/bytecode.c AND src/jacl.h — BOTH must be updated when adding new opcodes
- No `jacl_is_true()` function exists — compare with `JACL_TRUE` constant directly
- JACL strings have `$var` interpolation — `"[+ $x 1]"` tries to resolve `$x` in the enclosing scope. To embed literal `$var` in a string, use `[concat "prefix" "$" "var suffix"]`
- OP_INTERPRET uses an arity byte (1 or 2) after the opcode — existing 1-arg form and new 2-arg form share one opcode
- For 2-arg interpret, env entries must be set BEFORE inner compilation/execution and cleaned up by restoring env.count after

- **Learnings for future iterations:**
  - To run top-level compiled code from within `vm__run`, you CANNOT use `vm_exec` (it resets the stack). Instead, save state, push dummy callee, set up a CallFrame at the current stack_top, and call `vm__run(vm, saved_frame_count)`. OP_HALT returns cleanly, and the result is at `stack_top - 1`.
  - OP_RETURN and OP_CHECK_ERROR write the return value to `stack[callee_base - 1]`, so you must push a dummy callee slot before the frame. Otherwise they clobber parent stack data.
  - `MacroEntry.is_builtin` is uninitialized when `macro_table_init` only zeros `count`. Stack garbage can make `is_builtin == true`, causing duplicate defmacros to silently override instead of erroring. Always set `is_builtin = false` for user-defined entries.
  - The HAMT map type for test assertions is `jacl_map_node*` (via `jacl_as_ptr()`), not `jacl_map_root*`.
