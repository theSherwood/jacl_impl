## M12/M13 Hardening — Lexer Overflow, Escape Analysis, Generational GC, E2E Stress Tests

Progress log for ralph/m12m13-hardening branch.

## Codebase Patterns
- Build and test with `bash build.sh` from project root
- JACL proc names must be <= 7 bytes (inline string limit). Use short names.
- `==` is the equality operator (not `=`)
- .jacl integration tests use `# mode: concurrent` and `# expect:` headers
- test_gc.c, test_m12.c, test_m13.c include `../src/jacl.c` directly (unity build pattern)
- Pre-existing compiler warnings in hamt.h, rrb_vec.h are expected — only check for new warnings
- GCHeader is 8 bytes: epoch(u32) + mark:1/gen:1/survive_count:2/_reserved:4 (bitfields) + obj_type(u8) + alloc_total(u16)
- gen field: 0 = young, 1 = old. Initialized to 0 in gc__bump_alloc. Independent of mark bit.
- Promotion: survive_count incremented each GC sweep; promoted (gen=1) when survive_count >= 1 at second sweep (2 cycles survived)
- The GC is non-moving. No compaction, no semi-spaces, no object relocation.
- gc_alloc is in src/gc.c, gc_collect/gc_sweep in src/gc_collect.c
- Write barrier (hybrid SATB + insertion) is in src/gc.c. Generational write barrier (gc_remembered_set_barrier) fires unconditionally alongside it.
- RememberedSet is per-thread (on WorkerThread), structurally identical to GreyBuffer. VM has remembered_set pointer (NULL in single-threaded mode).
- All mutable container mutation sites (OP_SET_CELL_LOCAL, OP_SET_CELL_UPVALUE, OP_RESET, OP_SWAP) call gc_remembered_set_barrier after gc_write_barrier
- When adding RememberedSet to WorkerThread, also update rt_test__init_no_threads / rt_test__destroy_no_threads in ALL test files (test_m12.c, test_m13.c, test_runtime.c)
- Worker pinning infrastructure: pin_all_closures flag in compiler, pinned/pin_worker_id on JaclClosure, runtime__push_pinned() in runtime.c
- ast__contains_nonlocal_set() scans AST for set! usage to decide pinning
- compiler__body_captures_mutable() checks $var refs to mutable bindings for pinning
- Both checks are ORed together: either triggers pinning for spawn/parallel/race bodies
- Bare `$var` in JACL is parsed as a zero-arg function call, NOT a value expression
- Transitive capture: `captures_mutable` flag on Local/Upvalue/GlobalArity propagates through upvalue resolution and continuation eager capture
- To call a closure captured from enclosing scope in a spawn body, use `[$f]` (var ref call), not `[f]` (name call) — name calls only resolve builtins/globals

- Split the mark uint8_t into bitfields: mark:1, gen:1, _reserved:6 — header stays 8 bytes
- gen initialized to 0 (young) in gc__bump_alloc alongside other header fields
- All existing mark comparisons (`hdr->mark == mark`, `hdr->mark = mark`) work unchanged with 1-bit bitfield
- Added 5 tests in test/test_m12.c: header size, young-on-alloc, mark/gen independence, gen survives GC, header_of with gen
- Files changed: src/gc.c, test/test_m12.c
- **Learnings for future iterations:**
  - uint8_t bitfields are supported by GCC/Clang and pack correctly into a single byte
  - Bitfield approach is cleaner than bit masking — existing `hdr->mark` assignments/comparisons work unchanged since mark values are always 0 or 1
  - The gen field is preserved through mark/sweep because sweep only zeros dead objects and mark phase only writes the mark bitfield
  - The _reserved:6 bits are available for US-005's survive_count (2-bit counter for promotion threshold)

## 2026-03-10 - US-005
- Implemented promotion logic in sweep: young objects promoted to old (gen=1) after surviving 2 GC cycles
- Added `survive_count` 2-bit field to GCHeader (from reserved bits): mark:1, gen:1, survive_count:2, _reserved:4
- Initialized survive_count=0 in gc__bump_alloc alongside other header fields
- Added promotion logic to both gc_sweep (single-threaded) and gc_sweep_concurrent (concurrent): on live object, if gen==0, increment survive_count; if survive_count>=1 at sweep time, promote (gen=1)
- Added 5 tests: promote_after_2_cycles, no_promote_after_1_cycle, dead_not_promoted, old_stays_old, promote_multiple_objects
- Files changed: src/gc.c, src/gc_collect.c, test/test_m12.c
- **Learnings for future iterations:**
  - Promotion threshold of 2 means: survive_count incremented to 1 on first survival, then on second survival sc>=1 triggers promotion
  - Already-old objects (gen==1) skip the promotion check entirely — no survive_count overflow concern
  - Both sweep paths (single-threaded gc_sweep and concurrent gc_sweep_concurrent) need the same promotion logic
  - The survive_count field persists across GC cycles because sweep only zeros dead objects, not live ones
