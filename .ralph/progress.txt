## Codebase Patterns
- lexer.c, parser.c, compiler.c are all #included into jacl.c (unity build) — no separate compilation
- Test files include "../src/jacl.c" directly, giving them access to all internal types
- TOKEN_WORD is used for command heads and args; keyword tokens (TOKEN_DEF, TOKEN_IF, etc.) must be added to parser__parse_atom() and parser__parse_expr() switch to remain usable as atoms
- When `struct` keyword was TOKEN_WORD, inline struct type parsing searched for TOKEN_WORD "struct"; now must check TOKEN_STRUCT too
- TOKEN_OPERATOR is still used for compound operators (==, !=, <=, >=, +, -, *, /, etc.); single-char operators now have specific token types
- Words with ! suffix (like set!, reset!) are still TOKEN_WORD because lexer__is_word_char includes !
- defstruct keyword now emits TOKEN_STRUCT for backward compat; both defstruct and struct parse the same way
- pre-existing failures: rdoc, nfa_rdoc, nfa_cross (double-free in lib/ tests, unrelated to JACL language)
- () is now infix mode: parser__parse_infix parses left-to-right with no precedence; nested () for explicit grouping
- For adding new expression forms, add dispatch in parser__parse_expr AND in parser__parse_infix_operand (for use inside ())
- New keyword-based syntax forms (proc, struct, if, etc.) need lookahead in parser__parse_bare_command to detect new vs old syntax
- New proc syntax uses TWO {} blocks ({params} {body}); distinguish from old syntax (ONE {} block) by scanning for matching } then checking for second {
- parser__parse_proc_params builds flat AST_COMMAND from comma-separated {type name, type name} — same shape as old [type name type name] params
