## Codebase Patterns
- Single-header convention: `#ifndef X_H` / `#define X_H` for declarations, `#ifdef X_IMPLEMENTATION` / `#ifndef X_IMPL_GUARD_` for implementation
- Arena allocator: zero-init `arena_t arena = {0}`, uses libc by default, lazy-initializes on first alloc
- Test tracked allocator: `tracked_allocator` from `test/test_helpers.h`, plug into arena via `.allocator = tracked_allocator`
- Build system: `build.sh` with `TESTS=()` array entries formatted as `"path/test.c|name|optional_extra_cflags"`
- Compiler flags: `-Wall -Wextra -std=c99 -g`
- Relative includes from module dirs use `../` prefix (e.g., `#include "../arena/arena.h"`)
- Token payload.text for WORD/KEYWORD/OPERATOR points into the original source buffer (zero-copy)
- Character classification helpers: `lexer__is_word_start`, `lexer__is_word_char`, `lexer__is_operator_char`
- Words start with letter/underscore/UTF-8 (>=0x80); continue with those plus digits and hyphens
- Operator chars: `!%&*+-./<=>?@\^|~` — consumed greedily
- `-` is both a word continuation char and an operator start char; context (word vs new token) determines which
- VAR token payload.text skips `$` prefix (points to `source + start + 1`); token.length includes `$`
- Error recovery for prefix chars (like `$`): only consume the prefix, let following chars lex independently
- Number literals: digits at token start trigger number handler; negative numbers are handled by parser (unary minus), not lexer
- Hex/binary prefixes: `0x`/`0X` and `0b`/`0B`; parse with `int64_t` intermediate to avoid overflow, cast to `int32_t` at end
- Float parsing: integer arithmetic (frac/frac_div) avoids float accumulation errors; `3.` with no trailing digit is INT + OPERATOR(`.`)
- Number suffix validation: after consuming number, check `lexer__is_word_start` — if true, consume remaining word chars and emit ERROR
- String tokens: `payload.text` points to arena-allocated null-terminated buffer (NOT source); `token.length` is source length including quotes
- StringBuf helper: arena-backed growable char buffer (init 64, doubles), used for building processed string content
- `lexer__encode_utf8(cp, out)`: encode codepoint to UTF-8 bytes, returns byte count (1-4)
- `lexer__hex_digit(c)`: parse single hex digit, returns -1 on invalid
- String error recovery: on invalid escape, skip to closing `"` (handling `\"` inside), emit ERROR spanning entire string
- Embedded newlines in strings: normalize `\r\n`/`\r` to `\n`, track `lex.line`/`lex.col` for correct positions after string
- Interpolation in strings: `$` + word-start or `$[` triggers interpolation; bare `$` (followed by digit, quote, etc.) is a regular char
- Interpolated strings emit: STRING_BEGIN, INTERP_VAR/INTERP_EXPR_START...INTERP_EXPR_END, STRING_PART (between interpolations), STRING_END
- Non-interpolated strings still emit a single STRING token (backward compatible)
- String handler refactored into `lexer__lex_string_body()` — called from main loop and from interp expr sub-lexer (mutual recursion)
- `lexer__lex_interp_expr()` tracks bracket depth; `$[` inside expressions emits DOLLAR_BRACKET and increments depth
- Number handler extracted to `lexer__lex_number()` — shared by main loop and interp expr sub-lexer
- Escape handling extracted to `lexer__handle_escape()` — single source of truth for all escape sequences
- Error recovery extracted to `lexer__skip_to_string_end()` — handles `\"` escapes and newline tracking during skip
- `lexer__unexpected_char_msg(lex, c)` — arena-allocated error message with hex representation of unexpected chars
- Unrecognized characters: anything not handled by specific handlers (control chars, bare `:`, `,`, `;`, etc.) → ERROR
- Characters >= 0x80 are treated as word-start, so only single-byte non-handled chars reach the error handler
