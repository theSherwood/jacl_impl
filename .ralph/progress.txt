## Codebase Patterns
- Unity build: `src/jacl.c` #includes all pipeline .c files + lib headers as a single translation unit
- JACL pipeline files in `src/`: plain .c with `#ifndef X_C` guards, no `#define X_IMPLEMENTATION` needed
- Lib modules in `lib/`: single-header convention with `#ifdef X_IMPLEMENTATION`
- Test files: `#include "test_helpers.h"` then `#include "../src/jacl.c"` — gets everything
- Arena allocator: zero-init `arena_t arena = {0}`, uses libc by default
- Test tracked allocator: `tracked_allocator` from `test/test_helpers.h`, plug into arena via `.allocator = tracked_allocator`
- Build system: `build.sh` with `TESTS=()` array entries formatted as `"path/test.c|name|optional_extra_cflags"`
- Compiler flags: `-Wall -Wextra -std=c99 -g`
- Implementation language is C (C99)
- Pipeline: src/value.c → src/string.c → src/lexer.c → src/ast.c → src/parser.c → src/bytecode.c → src/compiler.c → src/vm.c
- Private/internal functions use double-underscore prefix: `module__function_name`
- Public types use PascalCase (Token, LexResult, AstNode) or lower_t for system-level (arena_t)
- Public functions use module_verb_noun pattern (lexer_lex, arena_alloc, parser_parse)
- Constants and macros use ALL_CAPS (TOKEN_EOF, JACL_TAG_NIL)
- Test functions are `static int test_name(void)` returning 0=fail, 1=pass
- Test main() uses table-driven pattern: array of {name, fn} structs, iterates and counts pass/fail
- Memory leak check pattern: setup() -> exercise -> teardown() -> ASSERT(check_no_leaks()) -> TEST_PASS()
- Tests grouped by US-XXX story comments in the test table

- Lexer API: LexResult lexer_lex(const char* source, arena_t* arena)
- Parser API: ParseResult parser_parse(LexResult tokens, arena_t* arena)
- Compiler API: CompileResult compiler_compile(ParseResult, arena_t*) in src/compiler.c
- VM API: VM struct in src/vm.c, vm_init(VM*, arena_t*), vm_exec(VM*, BytecodeChunk*)
- Pipeline API: jacl_run(source, vm, arena) in src/vm.c

- Value API: JaclVal is uint64_t with tag byte (bits 63-56) + 56-bit payload
- JACL_TAG_STRING (0x05) already reserved in value.c for heap string values
- JACL_TAG_INLINE_STRING (0x04) for strings up to 7 bytes stored in payload
- JACL_TAG_CLOSURE (0x08) for closure values
- Existing inline string helpers: jacl_inline_string(), jacl_inline_string_len(), jacl_inline_string_get(), jacl_is_inline_string()
- Existing generic pointer helpers: jacl_string_ptr() constructor, jacl_as_ptr() extractor
- Existing opcodes: OP_CONST, OP_NIL, OP_TRUE, OP_FALSE, OP_POP, OP_ADD..OP_MOD, OP_NEG, OP_EQ..OP_GE, OP_PRINT, OP_DEF_GLOBAL, OP_GET_GLOBAL, OP_GET_LOCAL, OP_SET_LOCAL, OP_GET_UPVALUE, OP_JUMP, OP_JUMP_IF_FALSE, OP_LOOP, OP_CALL, OP_RETURN, OP_CLOSURE, OP_POP_N, OP_HALT
- VM has single Environment (flat name/value arrays) for globals, pre-populated with true/false/nil
- Compiler dispatches builtins via compiler__head_matches if-chain in compiler__compile_command
- AST_BLOCK compilation: begin_scope, compile stmts with OP_POP after each, end_scope (OP_POP_N), push OP_NIL
- Compiler Local struct: { JaclVal name, int depth }, COMPILER_LOCALS_MAX = 256
- Compiler scope_depth: 0 = top-level (globals), >0 = inside block/function (locals)
- JaclClosure struct is in bytecode.c (not value.c) because it contains BytecodeChunk by value
- Typed closure helpers jacl_closure()/jacl_as_closure() are in bytecode.c; generic pointer helpers in value.c
- VM_FRAMES_MAX = 64; CallFrame struct: closure, return_ip, stack_base, chunk pointer
- vm_exec wraps top-level code in implicit JaclClosure (stack-allocated) for uniform frame-based execution
- Truthiness: only nil and JACL_FALSE are falsy; 0, empty string, etc. are truthy
- In JACL, bare `false` is a string (truthy); `$false` is the boolean false (falsy)
- Jump patching: compiler__emit_jump emits placeholder 0xFFFF, compiler__patch_jump fills in actual offset
- compiler__compile_block_expr: compiles block as expression (last stmt value stays on stack)
- Block commands inside { } must be separated by `;` or `\n`
- VM stack: JaclVal stack[256], stack_top is next free slot
- PrintCapture test pattern: struct {buf[1024], len} with capture_print callback

## M5-Specific Context
- Lexer already fully handles string interpolation: TOKEN_STRING, TOKEN_STRING_BEGIN/PART/END, TOKEN_INTERP_VAR, TOKEN_INTERP_EXPR_START/END
- Parser already builds AST_LIT_STRING and AST_INTERP_STRING nodes
- AST_LIT_STRING: { const char* value; uint32_t length; }
- AST_INTERP_STRING: { AstNode** segments; uint32_t count; } — segments are AST_LIT_STRING, AST_VAR_REF, or AST_COMMAND
- Compiler currently rejects strings > 7 bytes with error "string literal exceeds 7-byte inline limit"
- Compiler currently rejects AST_INTERP_STRING with error "interpolated strings not yet supported"
- No string comparison operators exist yet (== only works for numeric types)
- No string concatenation opcode or builtin exists
- Rope library (lib/sum_tree/rope.h) exists but is NOT used in M5 — deferred to later
- Key design: heap strings are NOT null-terminated, carry uint32_t length field
- String API: JaclHeapString struct in src/string.c: { uint32_t length, uint32_t hash, char data[] }
- Intern table: JaclInternTable struct, open addressing + linear probing, intern_table_init(), jacl_intern()
- jacl_is_heap_string() / jacl_as_heap_string() extractors in src/string.c
- FNV-1a hash: string__fnv1a(data, length) operates on byte data, length-aware (no null-terminator)
- Intern table resizes at > 0.75 load factor, initial cap 16
- Unified string API in src/string.c: jacl_string_len(), jacl_string_data(), jacl_string_eq(), jacl_string_cmp()
- jacl_is_string() in value.c returns true for BOTH inline and heap strings; use jacl_is_heap_string() for heap-only check
- jacl_string_data() copies into caller-provided buffer, returns actual length (may exceed buflen)
- jacl_string_cmp() uses direct pointer to heap data, stack buffer for inline data
- Compiler has JaclInternTable* intern_table field; compiler_compile() takes it as 3rd param
- jacl_run() creates a JaclInternTable on the stack and passes it to compiler_compile()
- Body compilers (proc) inherit the intern_table from the parent compiler
- compile_source() test helper in test_compiler.c creates its own JaclInternTable
