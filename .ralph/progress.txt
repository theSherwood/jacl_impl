# Ralph Progress Log
Started: Tue Apr 29 2026
Feature: Implicit Context ($ctx) — Pool-allocated struct, explicit forking, per-field mutability

## Codebase Patterns
- StructTypeField is defined in BOTH `src/ast.c` (used by unity build) AND `src/jacl.h` (public API) — update both when changing struct type definitions
- StructTypeDef/StructTypeField/StructTypeRegistry are similarly duplicated between `src/compiler.c` and `src/jacl.h`
- Struct field mutation paths: inline (OP_STRUCT_SET_INLINE), heap (OP_STRUCT_SET), upvalue (OP_STRUCT_SET_UPVALUE), dynamic (OP_STRUCT_SET_DYN) — all four need updating for field-level checks
- Parser `mut` keyword token: TOKEN_MUT already existed in lexer, no new token needed
- Test patterns: `# expect-error:` for compile errors, `# expect:` for output validation in .jacl files
- C embedding API (jacl_struct_set_val in embed.c) bypasses compiler checks — operates at raw level
- Unity build order: value.c → gc.c → string.c → lexer.c → ast.c → parser.c → bytecode.c → collections.c → compiler.c → vm.c → syntax.c → gc_collect.c → runtime.c → embed.c
- TokenType enum is duplicated in BOTH `src/lexer.c` AND `src/jacl.h` — add new tokens to both
- New AST node types must also be handled in `src/syntax.c` (syntax_from_ast switch) to avoid -Wswitch warnings
- `jacl_run()` in vm.c now extracts actual parse error messages recursively from AST_ERROR nodes (not just "parse error")
- Parse error messages from jacl_run() are prefixed with "parse error: " for backwards compatibility
- ctx keyword: TOKEN_CTX in lexer, AST_CTX_DECL in parser, CtxFieldList collection in compiler
- Compiler struct is duplicated in `src/compiler.c` AND `src/jacl.h` — adding new fields requires updating BOTH (size mismatch causes stack corruption in tests)
- CtxFieldList is on root compiler, shared with module compilers via enclosing chain (like struct_registry)
- ctx struct is always registered via ctx_field_list__finalize after compilation; ctx_type_idx stored on StructTypeRegistry
- Tests that hard-code struct_registry->count need +1 when ctx struct is added
