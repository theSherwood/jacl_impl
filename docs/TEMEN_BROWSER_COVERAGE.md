> Generated by `runtime/harness/src/bin/browser_coverage.rs`. Each `test/jacl/*.jacl`
> is linked vs the translated runtime and run on the **pure bytecode engine** with a
> name-bound powerbox — the exact path the `temen-browser` cdylib's `temen_run_onramp`
> takes (no tree-walker fallback). `unsupported` = the engine declined the module
> (`STATUS_UNSUPPORTED` in the browser); `trap` = it ran but faulted.

> The powerbox grants only `stdout`/`stdin`/`exit` (a browser sandbox has no
> shell or filesystem), so a program that shells out (`!cmd`) or reads/writes files
> (`read-file`/`write-file`) is a **capability** miss, not an engine gap. Zero
> `unsupported`/`trap` means the wasm-safe bytecode engine itself runs everything else.
